# 設計

ML-Pathfinder の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

機械学習に向けた問題を設計するローカルの Web アプリ. 「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作る) のうち, 「問題の設定」の段階の画面.

- 課題から始め, 決まった順の問いに答えて, どの部分を機械学習に任せると課題が解けるかを決める. 機械学習が要らないと分かればそこで終える
- 答えるたびに, 確かめ (食い違いと足りない答え), 筋道 (要約の文), 後ろの段階に渡す値を見せる
- 骨組みを組める答えがそろえば, ML-Found のプロジェクトの骨組みを書き出す (「直す」が残っていれば, 一覧を確かめてから)
- 構成と道具は ML-Provide にそろえる (FastAPI と React, 起動ごとのトークン, 置き場, Playwright の通しのテスト)

## 2. 使うライブラリと約束

ライブラリは ML-Quest (submodule).

- 画面は ML-Quest だけを使う. 問いの並び, 選択肢, 確かめ, 受け渡しの値, 要約の文, 骨組みは全て ML-Quest が返し, 画面は固定で持たない (節の名前と見本の名前も `/api/info` から)
- 読み書きするファイル:

| ファイル | 読むか書くか | 約束 |
| --- | --- | --- |
| `problem.yaml` (問題の設定) | 読み書き | ML-Quest の形. 版 1 と版 2 を読み, 版 2 で書く (下の「3. 画面」). 知っている版より新しいものは開かない |
| 表のファイル, ML-EDA のデータセット (`dataset.yaml` の版 2) | 読む (置き場に写す) | ML-EDA の読み込み. 写した場所と読み方を `problem.yaml` に持つ |
| 学習のプロジェクトの骨組み (config, `train.py`, README, `problem.yaml` の写し) | 書く | ML-Quest の骨組み. ML-Found で学習する |

- 後ろの段階のアプリは, 問題の設定のファイルを ML-Quest を通して読む. つないでいるのは, データの分析の ML-Fathom (「問題の設定から始める」と書き戻し) と, 推論の ML-Provide (一式につないで損得を読む). 他の段階は, 利用者が「後ろの段階に渡す値」を見て各アプリで選ぶ

## 3. 画面

| 画面 | 内容 |
| --- | --- |
| 問題の設定の一覧 | 名前, 進み具合 (答えた要る問いの数), 渡せるか, 機械学習を使わないで終えたか. 新しく作る, 見本を開く, ファイルから取り込む |
| 問題の設定 | 左に 10 の節と進み具合, 中に節の問い, 右に筋道, 確かめ, 後ろの段階に渡す値. 名前の変更, `problem.yaml` の保存, 骨組みの書き出し, 消去 |

- 問いの入力は種類ごと. 文と数は欄を離れたとき (か Enter), 選択肢は選んだときに保存する. 要因と打てる手 (`levers`), 損得と制約 (`decision`) は複数の欄を書いてから「保存」を押す (書きかけは「保存していません」と出す). 意思決定の型を選ばずに保存すると答えを消す. 対象を選ぶ型は, 効果の渡し方 (防げる割合か, 行動したとき − しないときの当たりの確率) と, 確率の差のときだけ向き (当たりを減らしたいか増やしたいか) を選ぶ (ML-Quest の `effect_kind` と `effect_goal`. 使わない向きは保存しない)
- 守る指標 (2 の節) の続きの問い (向き, 守る線, 測り方) は, 名前を書くと出る (ML-Quest の問いの `applies` をそのまま使う. 画面は条件を評価しない)
- 後ろの段階に渡す値の分割は, 時刻の順, 相手ごと, 無作為, 層別の名前で出し, 相手をまとめる列 (`group_column`) があれば役目 (同じ値を同じ分割に / 重なりを確かめる) と一緒に出す
- 予測の使い道 (5 の節) で後段の仕組みか機械学習を選ぶと, 後段が求めるものの問いが出る. 守る制約 (7 の節) は 1 行に 1 つ
- 保存中は, その問いだけに印を出し, 他の問いは書き続けられる (入力を止めない). 保存の誤りはその問いの下に出し, 選択肢は保存した値に戻す
- 全ての節の問いを置いて今の節だけを見せる (節を移っても書きかけが消えないように)
- 確かめから「n. 節 の問いへ」で, その問いの入力に移る
- 狭い画面では, 節を選ぶ欄と 1 列の並びにする
- 手元のデータ (5 の「手元のデータは」) を入れると, ML-Quest の `inspect_data` の答えの候補を問いの下に出す. 押すと答えになる (列の並びの問いは今の答えに足す. 選択肢の問いは選択肢の名前で出す. 読み直す間は押せない). データの確かめも右の確かめと問いの下に並べる. 入れたデータは外せる. 課題, 指標, 分解, 決めること (1 から 4) はデータ無しで答える順のまま. データは問題の設定ごとの置き場 (`problems/<識別子>/data/`) に写し, 写した場所と ML-EDA の読み方を問題の設定に持つ (元のデータは変えない. 全体のシステムでは, ML-Fathom が同じ場所を同じ読み方で開き, 目的の列, 分割, 除く列を決めた状態で始め, そこで変えた選び方は問題の設定に書き戻す. 部品は ML-Quest の `recipe_from` と `apply_recipe`)
- 7 の「今のやり方をデータで書くと」は, 種類 (k 期前と同じ, 直前の k 期の平均, 今のやり方の値の列) と期の数か列を選んで保存する. データを入れていれば, 今のやり方の損の文が問いの下に, 損が 2 の「今の値は」の候補に出る
- 列の名前の問いは, 使えるデータの列 (5 の「使えるデータの列は」) があればそこから選ぶ (無ければ 1 行に 1 つ書く). 列の一覧に無い古い答えは「列にありません」の印を付けて出し, 外せるようにする. 使えるデータの列はデータのファイルの 1 行目から読める
- 今の答えのもとで要らない問いは出さない (ML-Quest の `applies`)
- 5 の節の頭では, 型に依らない問い (受け持ち, 1 件の単位, 出力の形, 正解の出どころ, 作り方) と, 予測すると作るでは正解の種類を問う. 目的の列やタスクの問いは, 受け持ちが「予測する」で正解の種類が「表の列」(列の予測) のときだけ出る. 問いと選択肢は ML-Quest の問いの並び (`ml.parts.0.*`) をそのまま描き, 画面は写して持たない. 正解の出どころが今の処理の出力なら, 処理の名前と設定の問いが出る. 最良を選ぶ指標で「その他」を選ぶと, 名前と向き (大きいほど良いか小さいほど良いか) の問いが出る
- 選択肢の問いの保存した答えが, 今の選択肢 (受け持ちなどで絞られる) に無ければ, 「今の答えに合いません」の印を付けて出す (確かめの誤りと一緒に, 何を選び直すかが分かるように. 選び直すか, 「答えを外す」で消せる). 任意の選択肢とはいかいいえの問い (方策か, 集め方, GPU が要るかなど) も, 答えた後に「答えを外す」で空に戻せる (分からなければ空のままにする問いのため)
- 後ろの段階に渡す値は, 列の予測なら, 目的の列, タスク, 分割, 使う列と除く列, 意思決定を出す. 列の予測でなければ, 受け持ち, 1 件の単位, 出力の形, 正解の種類と出どころ (今の処理なら処理の名前と設定. その処理を超えられないことを添える), 作り方, 監視する指標と向き, 入れたデータの場所を出す (目的の列, 分割, 意思決定は渡さない)
- 学習のプロジェクトの書き出しは, 列の予測か, 予測するで正解の種類が画像の領域 (`mask`) か点群 (`point_cloud`) の場合で, 最良を選ぶ指標がその他でないときと, 作るで正解の種類と出力の形が画像 (`image`. 条件の無い画像の生成) で, 最良を選ぶ指標が損失 (`loss`) のときと, 効果を見積もるで方策 (続けて行動を選ぶ) と答え, 集め方が今ある記録でなく, 最良を選ぶ指標が損失のとき (ML-Quest の骨組みが書けるもの). 領域と点群は, ML-EDA の版 2 のデータセットを入れていればそれを骨組みの `data/` に写し, 入れていなければ README で書き出しを案内する骨組みになる (データ無しでも書き出せる). 入れたデータセットの受け持ちか正解の種類が合わなければ書き出せない. 画像の生成は, 入れた画像のディレクトリを `data/` に写す (入れていなくても書き出せる). 決まりは ML-Quest の `project_error` だけが持ち, 画面はその文をボタンの下に出す (画面に同じ決まりを写して持たない)
- 書き出すボタンを押せないのは骨組みを組めないとき (`exportable` が偽) だけ. 骨組みを組めても「直す」(`open_errors`) が残っていれば, ボタンの下にその数を出し, 書き出す対話に一覧 (問いの節と題, 確かめの文) と「それでも書き出す」の確かめの欄を出す. 確かめるまで対話の「書き出す」は押せず, 確かめたときだけ `accept_errors: true` を送る (試しに書き出して進む使い方を止めず, 見落としたまま進むことを防ぐため). 確かめは確かめた一覧の印で覚え, 一覧が変われば確かめ直す. 409 が返れば問題の設定を読み直して今の一覧を出す. 一覧は見出しと名前の付いた並びにし, 確かめの欄は説明の文につなぎ, 押せない「書き出す」は一覧の見出しにつなぐ (読み上げで理由が分かるように)
- 書き出す対話の説明の出し分け (列の予測か, 領域と点群か, 画像の生成か) は, 問いの答えの正解の種類 (`ml.parts.0.target.kind`) と受け持ち (`ml.parts.0.role`) で決める (受け渡しの値は「直す」が残ると無いため). 損得と制約の「直す」で推論の一式に意思決定の既定値が付かない注意は, 列の予測だけに出す (他の型の一式は意思決定を持たないため)
- 書き出すと, その場所を ML-Quest の `record_project` で問題の設定の `project` (プロジェクト, データセットの書き出し先, モデルの定義の置き場. どれも絶対パス) に記録して保存する. 後ろの段階のアプリ (ML-Fathom など) がこの記録から場所を読み, 利用者が写さずに済むように. 書き出しと記録は編集の鍵の中で行い, 他の保存と食い違わない. 後ろの段階に渡す値に「学習のプロジェクト」として出す (書き出し直すと置き換わる)
- モデルの作成の入力の形は, 書き出したデータセットから決まると出す (表と時系列は学習に使う列の数, 画像, 文, 点群の列は 1 件の配列の形. 列の数とは限らないため)
- 手元のデータには, 表のファイルのほかに ML-EDA の版 2 のデータセットのディレクトリ (`dataset.yaml` を持つ. 画像と領域の対, 撮影と点群の対) も入れられる. データを選ぶ対話では, `dataset.yaml` を持つディレクトリに「データセット」の印を付け, ディレクトリのまま選べる. 表でないので概要 (行と列) は出さず, ML-Quest の `inspect_data` の確かめ (件数, 分割, 正解の種類と出どころの知らせ, 受け持ちに合わない誤り, 検証用の分割が無い警告) を問いの下と右の確かめに出す. 答えの候補は出ない
- 版 1 のファイル (古い ML-Quest や他のアプリが書いたもの) も開ける. ML-Quest が読むときに版 2 に移し, 次にこの問題の設定を変えると (答え, 名前, データの出し入れ, 列の読み込み) 版 2 で書く. それまでは画面の上に「版 1 のファイル」と出す (取り込みは置き場に写すときに版 2 で書く). 知っている版より新しいファイルは, 壊れたファイルと分けて「アプリを新しくしてから開く」と出し, 消すことは勧めない (新しいアプリが書いた正しいファイルを消さないように)
- 要る機能 (ML-Quest の `required_features`. 強化学習, MuJoCo, ROS2, CUDA) は, 答えの途中でも問題の設定の画面の上の方に「学習の段階の準備」のカードで出す (pip で入らないものは要るまで入れないので, 早めに知らせる). この画面では何も止めない. 入れ方は ML-Found が入っていれば登録簿 (`describe_requirements`. 入っているかは確かめない. この画面の環境は学習の環境と違うため) のコマンドと公式の手順の案内, 入っていなければ ML-Quest の `FEATURES` の名前と, 学習の環境で登録簿を見る補足. ML-Found はこのアプリの依存にしない
- 効果を見積もるで方策 (続けて自分で行動を選ぶ) と答えると, 受け渡しの `policy` (行動の上限, 止める条件, 外れたときの動き, 決めた行動, 安全の違反の信号の名前, 決める人) を後ろの段階に渡す値に「方策の守り」として出す. 方策を使ってよいかと守りの範囲は人 (決める人) が決め, 実機で動かすのは道具の外であることを添える
- 方策で環境の登録名の問い (ML-Quest の `ml.parts.0.env_id`. 任意. 集め方が今ある記録のときは要らない) が要るときは, 後ろの段階に渡す値に「方策を学ぶ環境」を出す. 答えていれば受け渡しの `policy.env_id` (Gymnasium の登録名. 骨組みは config の `env.id` に書き, 登録名で環境を作る), 答えていなければ自作の環境で, 骨組みに自作の環境の雛形 `env.py` を書き出すことと答え方を添える (空のままの意味を答える前後で分かるように. 問いの説明は ML-Quest の `help` をそのまま描き, 画面は写して持たない)
- 確かめの重さは「直す」(error), 「見直す」(warning), 「知らせ」(info). 問いの下にもその問いの確かめを出す
- 他のアプリ (ML-Fathom の書き戻し, ML-Provide は読むだけ) が問題の設定のファイルを書き換えたら読み直す. 画面に戻ったときと 10 秒ごとにファイルの中身の印 (sha256. 更新の時刻は秒の単位なので中身で) を確かめ, 変わっていれば読み直し, 値の変わった問いの入力だけを作り直して (他の問いの書きかけは残す) 「他で変わったので読み直しました」と出す. 保存の途中は待つ. 中身と印は同じ読み込みから作る (保存した後も読み直す. 保存の直後に他のアプリが書き換えても見逃さないように). 答えは 1 つずつ今のファイルに重ねて保存するので, 開いたままでも他の変更は消えない (同じ問いを両方で変えた場合は後の方が残る)

## 4. API

全て `/api` の下. 起動ごとのトークン (Cookie か `x-pathfinder-token` ヘッダー) が要る.

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/info` | 節, 見本の名前, 問題の設定の形の版 |
| GET | `/browse` | ディレクトリの中身 (ML-Found のプロジェクトと, ML-EDA のデータセット (`dataset.yaml` を持つディレクトリ) に印) |
| GET | `/problems` | 一覧 |
| POST | `/problems` | 名前か見本の名前から作る |
| POST | `/problems/import` | 手元の `problem.yaml` を写して取り込む. 写しの元の場所 (`origin`) は外す (取り込んだものが元になるため) |
| GET | `/problems/{id}` | 問題の設定と, 問い, 進み具合, 確かめ, 要約, 受け渡し, 要る機能と入れ方 (`requires`. 受け渡せる前から), 書き出せるか (`exportable` と組めない理由の `export_error`), 書き出すときに残っている直すところ (`open_errors`. 下), 書き出したプロジェクトの記録 (`project`. 無ければ null), ファイルの中身の印 (`version`) とファイルに書いてある版 (`file_version`). 保存して返す全ての応答も同じ |
| GET | `/problems/{id}/version` | ファイルの中身の印だけ (他での書き換えに気付くため. 軽い) |
| PUT | `/problems/{id}/answers` | 問いに答える (`null` で消す). 形の誤りは 400 |
| PUT | `/problems/{id}/name` | 名前を変える |
| POST | `/problems/{id}/columns` | データのファイルの 1 行目から使えるデータの列に答える |
| POST | `/problems/{id}/data` | 手元のデータを ML-EDA で読み, 場所と読み方と列の名前を入れる (版 2 のデータセットは読み方 `items` で, 列の名前は入れない. 大きなデータを読む間も他の答えを止めないように, 読むのは鍵の外. 場所は答えの PUT では変えられない) |
| DELETE | `/problems/{id}/data` | 入れたデータを外す (場所と読み方と置き場の写しを消す. 元のデータと要るのに無いデータは残す) |
| GET | `/problems/{id}/insight` | 入れたデータからの概要, 答えの候補, 確かめ (分析は重いので, 問題の設定ごとに, ML-Quest の分析の結果の印 (`inspect_key`. 答えとデータの場所, 大きさ, 更新の時刻. ディレクトリは中のファイルまで. プロジェクトの記録と元の場所は除く) が同じ間は覚えておく) |
| POST | `/problems/{id}/project` | 骨組みを書き出し, 場所を問題の設定に記録して保存する (`path`, `files`, `project` を返す. 骨組みを組めない問題の設定と, 上書きしない既にあるファイルは 400. 直すところが残っていて「それでも書き出す」(`accept_errors: true`) の指定が無ければ 409 で一覧を返す. 下) |
| GET | `/problems/{id}/download` | `problem.yaml` |
| DELETE | `/problems/{id}` | 消す |

- 答えは, 読んで答えて書く間を鍵で 1 つずつにする (同時の答えが消えないように)
- 識別子は 12 桁の 16 進. 形の違う識別子は置き場の外を指せないように 404
- 置き場の壊れたファイル (YAML として読めない, 版が無い, 形が崩れて確かめが落ちる) は, 一覧に「読めない」印で出し (一覧全体は止めない), 開くと 422 で理由を返し, 消せる (消すときは中身を読まない)
- 画面から受け取る場所 (取り込み, 列の読み込み, 書き出し) は絶対パスだけ (起動した場所で意味が変わらないように). 手元のファイルの誤りは日本語の文にする
- 骨組みの書き出しは, 書く前に書けるかを全て確かめる (ML-Quest. 一部だけが残らないように)
- 書き出せるか (`exportable`) は ML-Quest の `project_error` が `None` かだけで決める (受け渡しの値を作れるかは条件にしない. 「直す」が残っていても骨組みを組めれば, 確かめた上で書き出せるため). `export_error` はその文 (組めない理由)
- `open_errors` は ML-Quest の `open_errors` (骨組みを組める確かめの `error` と, 入れたデータの確かめの `error`. 項目は確かめと同じ `level`, `id`, `message`) で, 書き出せるときだけ求める (書き出せなければ空. 重いデータの分析をしないため). データの分析は `/insight` と同じ覚えた結果を渡し (無ければ求めて覚える), 詳しい画面だけで返す (一覧は分析しない). 覚える鍵を ML-Quest が覚えた結果を確かめる印と同じにするので, `/insight` と `open_errors` が食い違わず, ML-Quest が求め直すこともない (書き出しの記録を保存した後も同じ鍵). データの場所が文字列でない (手で書いたファイルの取り込みなど) 場合は, 分析せずに「データの場所は文字の場所 (パス) で書いてください」の確かめの `error` (`data.source`) にし, 書き出しは 400 にする (ML-Quest の確かめが場所の型を見ないので, 画面の側で). 場所を調べる権限が無く分析か印が `OSError` になる場合は, 「データを読めません: …」の `error` にしてログに残す. どちらも詳しい画面と `/insight` を止めず, 直すところには問題の設定の確かめの `error` と並べる. 他の例外は受け止めない (ML-Quest の不具合を読めないデータに見せないため) データを入れている問題の設定では, 答えを変えた応答がデータの分析を待つ (続く `/insight` は覚えた結果を返す)
- 書き出しは, 組めるときだけ重いデータの分析を保存の鍵の外で先に求めて覚え (他の保存を長く止めないように), 鍵の中では覚えた結果を使う (間に答えかデータが変わっていれば鍵の中で求め直す). 組めなければ分析せずに 400
- 書き出しの 409 の `detail` は `{"message": 画面の文, "open_errors": 一覧}`. ML-Quest の誤りの文 (ライブラリを使うコード向けの `accept_errors=True` の案内) は返さない. 書き出しの前に一覧を求め直すので, 画面が古い一覧で確かめていても, 残っていれば 409 か, 指定があれば今の一覧を README に残して書き出す

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| 問題の設定 | 課題から機械学習の受け持ちまでの答えをまとめたもの. `problem.yaml` (ML-Quest の形) |
| 節 | 問いのまとまり. 課題から運用までの 10 の節 |
| 確かめ | 答えどうしの食い違いと足りない答え. 重さは「直す」「見直す」「知らせ」 |
| 筋道 | 課題から行動までの要約の文 |
| 後ろの段階に渡す値 | ML-Quest の受け渡し (`handoff`). データの分析から推論までの段階が使う値 |
| 列の予測 | 受け持ちが予測する (`predict`) で, 正解の種類が表の列 (`column`) のもの |
| 骨組み | 書き出す ML-Found のプロジェクト (config, `train.py`, README, `problem.yaml` の写し). 写しは置き場の元の問題の設定の場所 (`origin`) を持つ (推論の段階が元を読み, 後で直した損得を使うため) |

## 6. 置き場

既定は `~/.ml-pathfinder/` (環境変数 `ML_PATHFINDER_HOME`).

- `problems/<識別子>/problem.yaml`: 問題の設定 (ML-Quest の形. 一時ファイルに書いてから置き換える)
- `problems/<識別子>/data/<写しごとの名前>/`: 入れたデータの写し. 入れるたびに別のサブディレクトリに写し (入れ直したファイルが読めなくても今の写しが残る), 写し終えたとき (失敗も含む) に, 写している途中の他の入れ直しが無ければ, 今の写し以外の写しを片付ける (写しの名前の形は ML-Quest と同じ). 写すのは鍵の外 (大きなデータでも他の保存を止めない). 鍵の中で, 写している間に問題の設定が消されていれば 404 (写しで作り直されたディレクトリも片付ける), 外されたか別のデータが入れられて写しが消えていれば 409 にする. 外すとき, 片付けるとき, 問題の設定を消すときは, 鍵の中で `.removing-...` に名前を変えるだけにし, 消すのは鍵の外 (消し損ねたものは次の片付けで消す). 書き出した `problem.yaml` は `data.origin` に元の場所を持つので, 置き場の写しが消えても元の場所から読める

## 7. 安全

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

- 識別子の形と, 画面から受け取る場所 (絶対パスだけ) を確かめる (上の「4. API」)
- 置き場の写しと元のデータを分け, 元のデータは書き換えない (上の「6. 置き場」)

## 8. 課題の型への広げ方

課題の型の分け方と広げる順は ML-Quest の docs/DESIGN.md の「課題の型への広げ方」. 問題の設定の問いと選択肢を広げるのは ML-Quest で, この画面はそれを描く. 版 2 の型に依らない問いと型ごとに分かれる問い, 守る指標と使い道と後段の問いは描ける (上の「3. 画面」). 意思決定の型と欄, タスクの名前は ML-Quest が返すもので描く. 節の数 (10) は画面が持つ.
