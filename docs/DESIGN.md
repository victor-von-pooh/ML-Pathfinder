# 設計

ML-Pathfinder の設計の方針をまとめる.

## 目的

機械学習に向けた問題を設計するローカルの Web アプリ. 問題の設定のライブラリ ML-Quest の画面.

- 課題から始め, 決まった順の問いに答えて, どの部分を機械学習に任せると課題が解けるかを決める. 機械学習が要らないと分かればそこで終える
- 答えるたびに, 確かめ (食い違いと足りない答え), 筋道 (要約の文), 後ろの段階に渡す値を見せる
- 直すところが無くなれば, ML-Found のプロジェクトの骨組みを書き出す

## 全体の中での役割

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「問題の設定」の段階の画面. ライブラリは ML-Quest.

- 画面は ML-Quest だけを使う. 問いの並び, 選択肢, 確かめ, 受け渡しの値, 要約の文, 骨組みは全て ML-Quest が返し, 画面は固定で持たない (節の名前と見本の名前も `/api/info` から)
- 後ろの段階のアプリ (ML-Fathom など) は, 問題の設定のファイルを直接は読まない. 今は利用者が「後ろの段階に渡す値」を見て各アプリで選ぶ (将来の 1 つのシステムでつなぐ)
- 構成と道具は ML-Provide にそろえる (FastAPI と React, 起動ごとのトークン, 置き場, Playwright の通しのテスト)

## 画面

| 画面 | 内容 |
| --- | --- |
| 問題の設定の一覧 | 名前, 進み具合 (答えた要る問いの数), 渡せるか, 機械学習を使わないで終えたか. 新しく作る, 見本を開く, ファイルから取り込む |
| 問題の設定 | 左に 10 の節と進み具合, 中に節の問い, 右に筋道, 確かめ, 後ろの段階に渡す値. 名前の変更, `problem.yaml` の保存, 骨組みの書き出し, 消去 |

- 問いの入力は種類ごと. 文と数は欄を離れたとき (か Enter), 選択肢は選んだときに保存する. 要因と打てる手 (`levers`), 損得と制約 (`decision`) は複数の欄を書いてから「保存」を押す (書きかけは「保存していません」と出す). 意思決定の型を選ばずに保存すると答えを消す
- 保存中は, その問いだけに印を出し, 他の問いは書き続けられる (入力を止めない). 保存の誤りはその問いの下に出し, 選択肢は保存した値に戻す
- 全ての節の問いを置いて今の節だけを見せる (節を移っても書きかけが消えないように)
- 確かめから「n. 節 の問いへ」で, その問いの入力に移る
- 狭い画面では, 節を選ぶ欄と 1 列の並びにする
- 手元のデータ (5 の「手元のデータは」) を入れると, ML-Quest の `inspect_data` の答えの候補を問いの下に出す. 押すと答えになる (列の並びの問いは今の答えに足す. 選択肢の問いは選択肢の名前で出す. 読み直す間は押せない). データの確かめも右の確かめと問いの下に並べる. 入れたデータは外せる. 課題, 指標, 分解, 決めること (1 から 4) はデータ無しで答える順のまま. データは問題の設定ごとの置き場 (`problems/<識別子>/data/`) に写し, 写した場所と ML-EDA の読み方を問題の設定に持つ (元のデータは変えない. 全体のシステムでは, ML-Fathom が同じ場所を同じ読み方で開き, 目的の列, 分割, 除く列を決めた状態で始め, そこで変えた選び方は問題の設定に書き戻す. 2026-11-17 にユーザーと決めた. 部品は ML-Quest の `recipe_from` と `apply_recipe`)
- 7 の「今のやり方をデータで書くと」は, 種類 (k 期前と同じ, 直前の k 期の平均, 今のやり方の値の列) と期の数か列を選んで保存する. データを入れていれば, 今のやり方の損の文が問いの下に, 損が 2 の「今の値は」の候補に出る
- 列の名前の問いは, 使えるデータの列 (5 の「使えるデータの列は」) があればそこから選ぶ (無ければ 1 行に 1 つ書く). 列の一覧に無い古い答えは「列にありません」の印を付けて出し, 外せるようにする. 使えるデータの列はデータのファイルの 1 行目から読める
- 今の答えのもとで要らない問いは出さない (ML-Quest の `applies`)
- 確かめの重さは「直す」(error), 「見直す」(warning), 「知らせ」(info). 問いの下にもその問いの確かめを出す

## API

全て `/api` の下. 起動ごとのトークン (Cookie か `x-pathfinder-token` ヘッダー) が要る.

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/info` | 節, 見本の名前, 問題の設定の形の版 |
| GET | `/browse` | ディレクトリの中身 (ML-Found のプロジェクトに印) |
| GET | `/problems` | 一覧 |
| POST | `/problems` | 名前か見本の名前から作る |
| POST | `/problems/import` | 手元の `problem.yaml` を写して取り込む |
| GET | `/problems/{id}` | 問題の設定と, 問い, 進み具合, 確かめ, 要約, 受け渡し |
| PUT | `/problems/{id}/answers` | 問いに答える (`null` で消す). 形の誤りは 400 |
| PUT | `/problems/{id}/name` | 名前を変える |
| POST | `/problems/{id}/columns` | データのファイルの 1 行目から使えるデータの列に答える |
| POST | `/problems/{id}/data` | 手元のデータを ML-EDA で読み, 場所と読み方と列の名前を入れる (大きなデータを読む間も他の答えを止めないように, 読むのは鍵の外. 場所は答えの PUT では変えられない) |
| DELETE | `/problems/{id}/data` | 入れたデータを外す (場所と読み方と置き場の写しを消す. 元のデータと要るのに無いデータは残す) |
| GET | `/problems/{id}/insight` | 入れたデータからの概要, 答えの候補, 確かめ (分析は重いので, データと候補に効く答えが同じ間は覚えておく) |
| POST | `/problems/{id}/project` | 骨組みを書き出す (渡せない問題の設定と, 上書きしない既にあるファイルは 400) |
| GET | `/problems/{id}/download` | `problem.yaml` |
| DELETE | `/problems/{id}` | 消す |

- 答えは, 読んで答えて書く間を鍵で 1 つずつにする (同時の答えが消えないように)
- 識別子は 12 桁の 16 進. 形の違う識別子は置き場の外を指せないように 404
- 置き場の壊れたファイル (YAML として読めない, 版が無い, 形が崩れて確かめが落ちる) は, 一覧に「読めない」印で出し (一覧全体は止めない), 開くと 422 で理由を返し, 消せる (消すときは中身を読まない)
- 画面から受け取る場所 (取り込み, 列の読み込み, 書き出し) は絶対パスだけ (起動した場所で意味が変わらないように). 手元のファイルの誤りは日本語の文にする
- 骨組みの書き出しは, 書く前に書けるかを全て確かめる (ML-Quest. 一部だけが残らないように)

## 置き場

既定は `~/.ml-pathfinder/` (環境変数 `ML_PATHFINDER_HOME`).

- `problems/<識別子>/problem.yaml`: 問題の設定 (ML-Quest の形. 一時ファイルに書いてから置き換える)
- `problems/<識別子>/data/<写しごとの名前>/`: 入れたデータの写し. 入れるたびに別のサブディレクトリに写し (入れ直したファイルが読めなくても今の写しが残る), 写し終えたとき (失敗も含む) に, 写している途中の他の入れ直しが無ければ, 今の写し以外の写しを片付ける (写しの名前の形は ML-Quest と同じ). 写すのは鍵の外 (大きなデータでも他の保存を止めない). 鍵の中で, 写している間に問題の設定が消されていれば 404 (写しで作り直されたディレクトリも片付ける), 外されたか別のデータが入れられて写しが消えていれば 409 にする. 外すとき, 片付けるとき, 問題の設定を消すときは, 鍵の中で `.removing-...` に名前を変えるだけにし, 消すのは鍵の外 (消し損ねたものは次の片付けで消す). 書き出した `problem.yaml` は `data.origin` に元の場所を持つので, 置き場の写しが消えても元の場所から読める

## 段階

| 段階 | 内容 |
| --- | --- |
| 1 | 問いに答える, 確かめ, 筋道, 受け渡し, 骨組みの書き出し, 見本, 取り込みと保存 |
| 2 | 実務に近い例で問いと見せ方を見直す. 損得の値を決める手伝い (値を変えたら行動がどう変わるか) |
| 3 | 将来の 1 つのシステムで, 後ろの段階のアプリに値を渡す |
