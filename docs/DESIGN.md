# 設計

ML-Pathfinder の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

機械学習に向けた問題を設計するローカルの Web アプリ. 「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作る) のうち, 「問題の設定」の段階の画面.

- 課題から始め, 決まった順の問いに答えて, どの部分を機械学習に任せると課題が解けるかを決める. 機械学習が要らないと分かればそこで終える
- 答えるたびに, 確かめ (食い違いと足りない答え), 筋道 (要約の文), 後ろの段階に渡す値を見せる
- 骨組みを組める答えがそろえば, ML-Found のプロジェクトの骨組みを書き出す (「直す」が残っていれば, 一覧を確かめてから)
- 構成と道具は ML-Provide にそろえる (FastAPI と React, 起動ごとのトークン, 置き場, Playwright の通しのテスト)

## 2. 使うライブラリと約束

ライブラリは ML-Quest (submodule).

- 画面は ML-Quest だけを使う. 問いの並び, 選択肢, 確かめ, 受け渡しの値, 要約の文, 骨組みは全て ML-Quest が返し, 画面は固定で持たない (節の名前, 見本の名前, 受け渡しの分割の名前とグループを使うか (ML-Quest の `SPLITS` の `value`, `label`, `grouped`. 説明の括弧の前までを短い名前にする. 分けない `none` も), 損得の値の幅を渡せる項目も `/api/info` から)
- 読み書きするファイル:

| ファイル | 読むか書くか | 約束 |
| --- | --- | --- |
| `problem.yaml` (問題の設定) | 読み書き | ML-Quest の形. 版 1 と版 2 を読み, 版 2 で書く (下の「3. 画面」). 知っている版より新しいものは開かない |
| 表のファイル, ML-EDA のデータセット (`dataset.yaml` の版 2) | 読む (置き場に写す) | ML-EDA の読み込み. 写した場所と読み方を `problem.yaml` に持つ |
| 学習のプロジェクトの骨組み (config, `train.py`, README, `problem.yaml` の写し) | 書く | ML-Quest の骨組み. ML-Found で学習する |

- 後ろの段階のアプリは, 問題の設定のファイルを ML-Quest を通して読む. つないでいるのは, データの分析の ML-Fathom (「問題の設定から始める」と書き戻し) と, 推論の ML-Provide (一式につないで損得を読む). モデルの作成の ML-CreateArchitecture と学習・評価の ML-Dashboard が問題の設定から始めるのに要る値 (モデルの定義の保存先, 受け持ちに合う雛形, 監視する指標と向き) も ML-Quest の受け渡しの値にあり, 画面は「後ろの段階に渡す値」に名前のまま出す (各アプリに入った値と見比べられるように)

## 3. 画面

| 画面 | 内容 |
| --- | --- |
| 問題の設定の一覧 | 名前, 進み具合 (答えた要る問いの数), 渡せるか, 機械学習を使わないで終えたか. 新しく作る, 見本を開く, ファイルから取り込む |
| 問題の設定 | 左に 10 の節と進み具合, 中に節の問い, 右に筋道, 確かめ, 後ろの段階に渡す値. 名前の変更, `problem.yaml` の保存, 骨組みの書き出し, 消去 |

- 問いの入力は種類ごと. 文と数は欄を離れたとき (か Enter), 選択肢は選んだときに保存する. 要因と打てる手 (`levers`), 損得と制約 (`decision`) は複数の欄を書いてから「保存」を押す (書きかけは「保存していません」と出す). 意思決定の型を選ばずに保存すると答えを消す. 対象を選ぶ型は, 効果の渡し方 (防げる割合か, 行動したとき − しないときの当たりの確率) と, 確率の差のときだけ向き (当たりを減らしたいか増やしたいか) を選ぶ (ML-Quest の `effect_kind` と `effect_goal`. 使わない向きは保存しない)
- 守る指標 (2 の節) の続きの問い (向き, 守る線, 測り方) は, 名前を書くと出る (ML-Quest の問いの `applies` をそのまま使う. 画面は条件を評価しない). 列の予測で, 数えられる量のある意思決定の型なら, 7 の節にたどり直しで数える量 (`issue.guard.counted`) の問いが出る. 選択肢は ML-Quest が意思決定の型で絞ったものをそのまま描く. 問いは識別子の頭 (`issue.*`) でなく節 (`section`) で置き, 並びは ML-Quest の問いの並びのまま
- 後ろの段階に渡す値の分割は, 時刻の順, 相手ごと, 無作為, 層別の名前で出し, 相手をまとめる列 (`group_column`) があれば役目と一緒に出す. 役目は分割の名前でなく ML-Quest の `SPLITS` の `grouped` で決め, グループを使う分割なら「同じ値を同じ分割に」, 使わない分割なら「分割をまたぐ重なりを確かめる」. `grouped` が分からない間 (分割の名前を読む前, 一覧に無い分割) は役目を出さない (違う役目を出さないため)
- 予測の使い道 (5 の節) で後段の仕組みか機械学習を選ぶと, 後段が求めるものの問いが出る. 守る制約 (7 の節) は 1 行に 1 つ
- 保存中は, その問いだけに印を出し, 他の問いは書き続けられる (入力を止めない). 保存の誤りはその問いの下に出し, 選択肢は保存した値に戻す
- 全ての節の問いを置いて今の節だけを見せる (節を移っても書きかけが消えないように)
- 確かめから「n. 節 の問いへ」で, その問いの入力に移る
- 狭い画面では, 節を選ぶ欄と 1 列の並びにする
- 手元のデータ (5 の「手元のデータは」) を入れると, ML-Quest の `inspect_data` の答えの候補を問いの下に出す. 押すと答えになる (列の並びの問いは今の答えに足す. 選択肢の問いは選択肢の名前で出す. 読み直す間は押せない). データの確かめも右の確かめと問いの下に並べる. 入れたデータは外せる. 手で書いた問題の設定で手元のデータの項目か場所が誤っている (場所が数や並び, 項目が辞書でない. ML-Quest の確かめの `data`, `data.source`, `data.origin` の `error`) 間は, 欄に「場所が誤っています」と誤りの文を出し, 「データを外す」と「データを入れ直す」を出す (入れ直す以外に直す道を残すため). その間は, 機械学習を使うと決める前でも欄を出し, 確かめの「問いへ」はこの欄に移る. 課題, 指標, 分解, 決めること (1 から 4) はデータ無しで答える順のまま. データは問題の設定ごとの置き場 (`problems/<識別子>/data/`) に写し, 写した場所と ML-EDA の読み方を問題の設定に持つ (元のデータは変えない. 全体のシステムでは, ML-Fathom が同じ場所を同じ読み方で開き, 目的の列, 分割, 除く列を決めた状態で始め, そこで変えた選び方は問題の設定に書き戻す. 部品は ML-Quest の `recipe_from` と `apply_recipe`)
- 7 の「今のやり方をデータで書くと」は, 種類 (k 期前と同じ, 直前の k 期の平均, 今のやり方の値の列) と期の数か列を選んで保存する. 種類と欄の名前は ML-Quest の問いの選択肢と欄 (`choices` と `fields`. 答えた意思決定の型に使える種類だけ) から描く. 保存した種類が今の選択肢に無い (意思決定の型を変えたなど) 場合は, 「(使えません)」の印を付けて残し, 選び直すか「書かない」で消すまで保存しない. データを入れていれば, 今のやり方の損の文が問いの下に, 損が 2 の「今の値は」の候補に出る
- 7 の「行動の損得と制約は」の下に「値を決める手伝い」を置く (値に自信の無い利用者が, どの値が決め手かを見てから決められるように). 開くと, 保存した意思決定の型の幅を渡せる項目 (ML-Quest の `SENSITIVITY_FIELDS`. `/api/info` から) ごとに, 保存した値と幅の下と上の欄を出す. 列で書いた項目 (行ごとの値) は出さず, 対象を選ぶ型の件数の上限と費用の上限は保存した方だけを出す (ML-Quest が両方を誤りにするため). 欄の名前は意思決定の欄の名前の括弧の前まで. 幅を書いた項目だけを点の数 (両端を含む 3, 5, 7, 9. 既定は 5) と「求める」で送る. 片方だけか数でない幅は送らずに誤りを出し, 他の誤り (ML-Quest の `ValueError`) はサーバーの文をそのまま画面の誤りに出す. データを読むので重く, 開いて「求める」を押したときだけ呼ぶ. 求めるのは保存した値からで, 保存した値が変われば古い結果を隠して求め直すよう出す
- 結果は, 保存した値での決め方の値 (と件数の上限), 知らせ (`notes`) をそのまま出し, 項目ごとに文 (`sentence`) と, 点ごとの値, 決め方の値, 件数の上限 (量を決める型の他), 選ぶか (対象を選ぶ型), 今のやり方の損 (時刻の列があれば 30 日あたり), 最も損の小さいやり方 (振り分ける型. ML-Quest の `best_label` の名前) の表を並べる. 並びは振れ幅 (`swing`) の大きい順で, データの上の損を求めた場合は今のやり方の損の振れ幅, 他は決め方の値の振れ幅で比べ, 同じなら件数の上限の振れ幅の順 (お金の差で比べられるときはそれを先にする). 項目が 2 つ以上で先頭の振れ幅が 0 より大きければ「決め手」の印を付ける. 行動の件数と量そのものは予測が要るので出さないことを, 欄の説明に書く
- 列の名前の問いは, 使えるデータの列 (5 の「使えるデータの列は」) があればそこから選ぶ (無ければ 1 行に 1 つ書く). 列の一覧に無い古い答えは「列にありません」の印を付けて出し, 外せるようにする. 使えるデータの列はデータのファイルの 1 行目から読める
- 今の答えのもとで要らない問いは出さない (ML-Quest の `applies`)
- 文の問いの欄は, ML-Quest の問いの欄の形 (`multiline`) で, 偽なら 1 行の入力 (名前で答える問い. 課題の持ち主, 指標の名前と単位, 環境の登録名, 承認する人など), 真なら複数行の入力にする (画面は問いの名前を写して持たない). 1 行の欄では, 前の答え (手で書いたファイルなど) の改行を空白にして出す (input は改行を消して詰めるため). 直さなければ保存せず, 直すと空白のまま保存する
- 5 の節の頭では, 型に依らない問い (受け持ち, 1 件の単位, 出力の形, 正解の出どころ, 作り方) と, 予測すると作るでは正解の種類を問う. 目的の列やタスクの問いは, 受け持ちが「予測する」で正解の種類が「表の列」(列の予測) のときだけ出る. 並べるで既製のモデルをそのまま使わないときは, 使えるデータの列の後に, 反応の表の利用者, 品物, 反応の時刻, 反応の強さ (任意) の列の問いと, 利用者ごとに並べる件数 (K) の問いが出る (列の問いは使えるデータの列から選ぶ). 問いと選択肢は ML-Quest の問いの並び (`ml.parts.0.*`) をそのまま描き, 画面は写して持たない. 正解の出どころが今の処理の出力なら, 処理の名前と設定の問いが出る. 最良を選ぶ指標で「その他」を選ぶと, 名前と向き (大きいほど良いか小さいほど良いか) の問いが出る. 方策では最良を選ぶ指標の先頭に報酬 (`reward`. 大きいほど良い) が出る (強化学習では報酬が大きいほど良いと読むのが普通なため). 方策でないと答えると選択肢から外れ, 選んであれば確かめに合わないと出る
- 選択肢の問いの保存した答えが, 今の選択肢 (受け持ちなどで絞られる) に無ければ, 「今の答えに合いません」の印を付けて出す (確かめの誤りと一緒に, 何を選び直すかが分かるように. 選び直すか, 「答えを外す」で消せる). 任意の選択肢とはいかいいえの問い (方策か, 集め方, GPU が要るかなど) も, 答えた後に「答えを外す」で空に戻せる (分からなければ空のままにする問いのため)
- 後ろの段階に渡す値は, 列の予測なら, 目的の列, タスク, 分割, 使う列と除く列, 意思決定を出す. 列の予測でなければ, 受け持ち, 1 件の単位, 出力の形, 正解の種類と出どころ (今の処理なら処理の名前と設定. その処理を超えられないことを添える), 作り方, 監視する指標と向き, 入れたデータの場所を出す (目的の列と意思決定は渡さない). 並べるで学習するときは, 受け渡しの `rank` を「並べ方」の欄に出す. 並べる件数 K は「利用者ごとに上位 K 件を並べる」の文にし, 列は名前に役割 (利用者ごとに品物を並べる, 並べる品物, 古い反応で学び新しい反応で確かめる, 0 より大きい行だけを反応とみなす) を添える (列の名前だけでは何に使うかが分からないため). 反応の強さの列が無ければ, 全ての行を反応とみなすと出す. 分割は時刻の順で, 反応の時刻の列を添える. 推論の欄には, 並べるの骨組みが, 利用者と品物の埋め込みを出力に持ち点数がその内積の定数倍の定義で学習すると, 実験の `inference/` に推論の一式を作ることを出す (仮のモデルや合わない定義では作らず, 学習の記録に理由が出る)
- 列の予測の推論の欄には, 受け渡しの守る指標 (`inference.guard`) の名前, 向き, 守る線を出す. たどり直しで数える量 (`counted`) は名前でなく, 7 の問いの選択肢の言葉 (説明) で出す (例えば `selected` に「選んだ件数」. 名前だけでは何を数えるか分からないため). 言葉は今の答えに合う選択肢から, 問いが要るときだけ引く (引けなければ名前を出す). 指さないと答えたときはその言葉を出し, 答えていなければ数える量の行は出さない
- 学習のプロジェクトの書き出しは, 列の予測か, 予測するで正解の種類が画像の領域 (`mask`) か点群 (`point_cloud`) の場合で, 最良を選ぶ指標がその他でないときと, 作るで正解の種類と出力の形が画像 (`image`. 条件の無い画像の生成) で, 最良を選ぶ指標が損失 (`loss`) のときと, 作るで正解の種類と出力の形が表 (`table`. 条件の無い表の生成. 合成のデータ) で, 最良を選ぶ指標が損失か列ごとの分布の近さ (`column_distance`) で, 入れたデータがあれば表のとき (入れていなくてもよい) と, 効果を見積もるで方策 (続けて行動を選ぶ) と答え, 集め方が今ある記録でなく, 最良を選ぶ指標が報酬 (`reward`) か損失のとき (ML-Quest の骨組みが書けるもの). 領域と点群は, ML-EDA の版 2 のデータセットを入れていればそれを骨組みの `data/` に写し, 入れていなければ README で書き出しを案内する骨組みになる (データ無しでも書き出せる). 入れたデータセットの受け持ちか正解の種類が合わなければ書き出せない. 画像の生成は, 入れた画像のディレクトリを `data/` に写す (入れていなくても書き出せる). 表の生成は, 入れた表のファイルを `data/` に写す (入れていなくても書き出せる). 並べるで既製のモデルをそのまま使わず, 出力の形が順位 (`ranking`) で, 入れたデータがあれば表のとき (入れていなくてもよい) も書き出せ, 入れた反応の表を `data/` に写してそのまま読む. 決まりは ML-Quest の `project_error` だけが持ち, 画面はその文をボタンの下に出す (画面に同じ決まりを写して持たない)
- 書き出すボタンを押せないのは骨組みを組めないとき (`exportable` が偽) だけ. 骨組みを組めても「直す」(`open_errors`) が残っていれば, ボタンの下にその数を出し, 書き出す対話に一覧 (問いの節と題, 確かめの文) と「それでも書き出す」の確かめの欄を出す. 確かめるまで対話の「書き出す」は押せず, 確かめたときだけ `accept_errors: true` を送る (試しに書き出して進む使い方を止めず, 見落としたまま進むことを防ぐため). 確かめは確かめた一覧の印で覚え, 一覧が変われば確かめ直す. 409 が返れば問題の設定を読み直して今の一覧を出す. 一覧は見出しと名前の付いた並びにし, 確かめの欄は説明の文につなぎ, 押せない「書き出す」は一覧の見出しにつなぐ (読み上げで理由が分かるように)
- 書き出す対話の説明の出し分け (列の予測か, 領域と点群か, 画像の生成か, 表の生成か, 並べるか, 方策か) は, 問いの答えの正解の種類 (`ml.parts.0.target.kind`), 受け持ち (`ml.parts.0.role`), 作り方 (`ml.parts.0.method`), 方策か (`ml.parts.0.autonomous`) で決める (受け渡しの値は「直す」が残ると無いため). 方策の次にすることは, 書き出した README の環境 (登録名を答えていればその環境, 無ければ `env.py` の雛形を書き換える), 守り, 学習, 守り付きの方策の一式の順にし, 実験の名前の既定は環境の登録名か `env` から (ML-Quest の `experiment_name` と同じ). 表の生成の次にすることは, 書き出した README のデータ (目的の列の無いレシピで検証用の分割を作る. 書き出した列を全て作るので, ID のような列と作らない列は落とし, 欠損は埋めるか行を落とす), モデルの定義 (同梱の例 `diffusion_denoiser` を, 列の数と種類の値の数に合わせて使える), 学習 (列ごとの分布の近さと作った表の見本で見る), 行の数と種で表を作る推論の一式の順にする. 並べるの次にすることは, 書き出した README の反応の表 (利用者, 品物, 時刻の列) を置く, モデルの定義 (同梱の例 `two_tower_retrieval` を, 利用者と品物の数に合わせて使える), 学習 (時刻の順に分け, 上位 K 件の Recall@K と NDCG を人気順と比べる), 推論の一式 (利用者と品物の埋め込みを出力に持ち, 点数がその内積の定数倍の定義なら, 学習の後に実験の `inference/` に作る) の順にし, 実験の名前の既定は品物の列と受け持ちから (ML-Quest の `experiment_name` と同じ). 損得と制約の「直す」で推論の一式に意思決定の既定値が付かない注意は, 列の予測だけに出す (他の型の一式は意思決定を持たないため). 書き出した後に出す置き場は, 記録したデータセットとモデルの定義のうち場所があるものだけ (方策の骨組みはモデルの定義だけを持つ). 対話の頭の説明と上書きの欄のファイルの並びも型に合わせる (方策は `model.py` と `env.py` を足す. どの型もデータを入れていれば `data/` に写す)
- 書き出すと, その場所を ML-Quest の `record_project` で問題の設定の `project` (プロジェクト, データセットの書き出し先, モデルの定義の置き場. どれも絶対パス) に記録して保存する. 後ろの段階のアプリ (ML-Fathom など) がこの記録から場所を読み, 利用者が写さずに済むように. 書き出しと記録は編集の鍵の中で行い, 他の保存と食い違わない. 後ろの段階に渡す値に「学習のプロジェクト」として出す (書き出し直すと置き換わる)
- モデルの作成の欄には, 受け渡しの `model.example` (ML-Quest の `model_example`. 受け持ちに合う ML-ModelControl の同梱の例の名前) を「モデルの作成の雛形: 名前 (モデルの作成の画面で開ける例)」の形で名前のまま出す (各アプリの画面と同じ名前で探せるように). `null` でも同じ見出しで, 作り方が一から学習のときは「受け持ちに合う雛形はありません (モデルの作成の画面で定義を選ぶ)」, 他の作り方では「一から学習しないので, 合う雛形はありません」と言葉で出す (雛形は学習前の定義で, 一から学習するときだけ渡るため). 既製のモデルをそのまま使う答えでは出さない
- 学習の欄には, 受け渡しの `training` の監視する指標 (`monitor`) と監視の向き (`mode`. `min` か `max`) を名前のまま出し, 向きには「小さいほど良い」か「大きいほど良い」を添える. 監視する指標には, 最良を選ぶ指標の選択肢の説明の括弧の前まで (例えば `valid/column_distance` に「作った表と本物の表の列ごとの分布の近さ」) を添える (名前だけでは何を測るか分からないため. その他は書いた名前なので添えない). 向きが `null` なら向きの行は出さない (違う向きを出さないため)
- モデルの作成の入力の形は, 書き出したデータセットから決まると出す (表と時系列は学習に使う列の数, 画像, 文, 点群の列は 1 件の配列の形. 列の数とは限らないため)
- 手元のデータには, 表のファイルのほかに ML-EDA の版 2 のデータセットのディレクトリ (`dataset.yaml` を持つ. 画像と領域の対, 撮影と点群の対) も入れられる. データを選ぶ対話では, `dataset.yaml` を持つディレクトリに「データセット」の印を付け, ディレクトリのまま選べる. 表でないので概要 (行と列) は出さず, ML-Quest の `inspect_data` の確かめ (件数, 分割, 正解の種類と出どころの知らせ, 受け持ちに合わない誤り, 検証用の分割が無い警告) を問いの下と右の確かめに出す. 答えの候補は出ない
- 版 1 のファイル (古い ML-Quest や他のアプリが書いたもの) も開ける. ML-Quest が読むときに版 2 に移し, 次にこの問題の設定を変えると (答え, 名前, データの出し入れ, 列の読み込み) 版 2 で書く. それまでは画面の上に「版 1 のファイル」と出す (取り込みは置き場に写すときに版 2 で書く). 知っている版より新しいファイルは, 壊れたファイルと分けて「アプリを新しくしてから開く」と出し, 消すことは勧めない (新しいアプリが書いた正しいファイルを消さないように)
- 要る機能 (ML-Quest の `required_features`. 強化学習, MuJoCo, ROS2, CUDA) は, 答えの途中でも問題の設定の画面の上の方に「学習の段階の準備」のカードで出す (pip で入らないものは要るまで入れないので, 早めに知らせる). この画面では何も止めない. 入れ方は ML-Found が入っていれば登録簿 (`describe_requirements`. 入っているかは確かめない. この画面の環境は学習の環境と違うため) のコマンドと公式の手順の案内, 入っていなければ ML-Quest の `FEATURES` の名前と, 学習の環境で登録簿を見る補足. ML-Found はこのアプリの依存にしない
- 効果を見積もるで方策 (続けて自分で行動を選ぶ) と答えると, 受け渡しの `policy` (行動の上限, 止める条件, 外れたときの動き, 決めた行動, 安全の違反の信号の名前, 決める人) を後ろの段階に渡す値に「方策の守り」として出す. 方策を使ってよいかと守りの範囲は人 (決める人) が決め, 実機で動かすのは道具の外であることを添える
- 方策で環境の登録名の問い (ML-Quest の `ml.parts.0.env_id`. 任意. 集め方が今ある記録のときは要らない) が要るときは, 後ろの段階に渡す値に「方策を学ぶ環境」を出す. 答えていれば受け渡しの `policy.env_id` (Gymnasium の登録名. 骨組みは config の `env.id` に書き, 登録名で環境を作る), 答えていなければ自作の環境で, 骨組みに自作の環境の雛形 `env.py` を書き出すことと答え方を添える (答え方は問いの節と題のリンクで, 押すとその問いの入力へ移る) (空のままの意味を答える前後で分かるように. 問いの説明は ML-Quest の `help` をそのまま描き, 画面は写して持たない)
- 予測するで作り方が既製のモデルをそのまま使う (`ml.parts.0.method` が `pretrained`) と, 受け渡しの `training` の指標, 監視, 向きは null になり (学習しないため), 後ろの段階に渡す値の「学習」の欄を出さず, モデルの作成は「モデルは作りません」と出す. 推論の `ready` (出どころ, モデル, 重み, hash. 受け渡しの `inference.ready`) は「推論」の欄に出す (出どころの名前は問いの選択肢から). hash を決めていないときは, 重みの版を固定していないこと (hash は重みのファイルの指紋) と, 一式を作ると求めた hash が出ることを添える
- 書き出す対話は, 既製のモデルのとき骨組みの型を「既製」にして (答えの `ml.parts.0.method` で決める), 書き出すファイルを config の `bundle.yaml`, `bundle.py`, README, `problem.yaml` の写しとし (`train.py` は無い), 実験の名前の既定はモデルと重みの名前から, 次にすることは一式づくり, hash の固定, ML-Provide への登録と推論の順に出す. 学習の言葉は出さない
- 確かめの重さは「直す」(error), 「見直す」(warning), 「知らせ」(info). 問いの下にもその問いの確かめを出す
- 他のアプリ (ML-Fathom の書き戻し, ML-Provide は読むだけ) が問題の設定のファイルを書き換えたら読み直す. 画面に戻ったときと 10 秒ごとにファイルの中身の印 (sha256. 更新の時刻は秒の単位なので中身で) を確かめ, 変わっていれば読み直し, 値の変わった問いの入力だけを作り直して (他の問いの書きかけは残す) 「他で変わったので読み直しました」と出す. 保存の途中は待つ. 中身と印は同じ読み込みから作る (保存した後も読み直す. 保存の直後に他のアプリが書き換えても見逃さないように). 答えは 1 つずつ今のファイルに重ねて保存するので, 開いたままでも他の変更は消えない (同じ問いを両方で変えた場合は後の方が残る)

## 4. API

全て `/api` の下. 起動ごとのトークン (Cookie か `x-pathfinder-token` ヘッダー) が要る.

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/info` | 節, 見本の名前, 問題の設定の形の版, 受け渡しの分割の名前とグループを使うか (`splits`), 意思決定の型ごとの幅を渡せる損得と制約の項目 (`sensitivity_fields`. ML-Quest の `SENSITIVITY_FIELDS`) |
| GET | `/browse` | ディレクトリの中身 (ML-Found のプロジェクトと, ML-EDA のデータセット (`dataset.yaml` を持つディレクトリ) に印) |
| GET | `/problems` | 一覧 |
| POST | `/problems` | 名前か見本の名前から作る |
| POST | `/problems/import` | 手元の `problem.yaml` を写して取り込む. 写しの元の場所 (`origin`) は外す (取り込んだものが元になるため) |
| GET | `/problems/{id}` | 問題の設定と, 問い, 進み具合, 確かめ, 要約, 受け渡し, 要る機能と入れ方 (`requires`. 受け渡せる前から), 書き出せるか (`exportable` と組めない理由の `export_error`), 書き出すときに残っている直すところ (`open_errors`. 下), 書き出したプロジェクトの記録 (`project`. 無ければ null), ファイルの中身の印 (`version`) とファイルに書いてある版 (`file_version`). 保存して返す全ての応答も同じ |
| GET | `/problems/{id}/version` | ファイルの中身の印だけ (他での書き換えに気付くため. 軽い) |
| PUT | `/problems/{id}/answers` | 問いに答える (`null` で消す). 形の誤りは 400 |
| PUT | `/problems/{id}/name` | 名前を変える |
| POST | `/problems/{id}/columns` | データのファイルの 1 行目から使えるデータの列に答える |
| POST | `/problems/{id}/data` | 手元のデータを ML-EDA で読み, 場所と読み方と列の名前を入れる (版 2 のデータセットは読み方 `items` で, 列の名前は入れない. 大きなデータを読む間も他の答えを止めないように, 読むのは鍵の外. 場所は答えの PUT では変えられない) |
| DELETE | `/problems/{id}/data` | 入れたデータを外す (場所と読み方と置き場の写しを消す. 元のデータと要るのに無いデータは残す) |
| GET | `/problems/{id}/insight` | 入れたデータからの概要, 答えの候補, 確かめ (分析は重いので, 問題の設定ごとに, ML-Quest の分析の結果の印 (`inspect_key`. 答えとデータの場所, 大きさ, 更新の時刻. ディレクトリは中のファイルまで. プロジェクトの記録と元の場所は除く) が同じ間は覚えておく) |
| POST | `/problems/{id}/sensitivity` | 損得と制約の項目ごとの幅 (`ranges`. `{"under_cost": [100, 300]}` のように下と上) と点の数 (`points`. 既定は 5. 2 から 21) から, 値を 1 つずつ変えたときの結論を返す (ML-Quest の `decision_sensitivity` の結果をそのまま. 形の確かめも ML-Quest に任せ, 誤りは 400 で ML-Quest の文. データを読むので重く, 覚えない) |
| POST | `/problems/{id}/project` | 骨組みを書き出し, 場所を問題の設定に記録して保存する (`path`, `files`, `project` を返す. 骨組みを組めない問題の設定と, 上書きしない既にあるファイルは 400. 直すところが残っていて「それでも書き出す」(`accept_errors: true`) の指定が無ければ 409 で一覧を返す. 下) |
| GET | `/problems/{id}/download` | `problem.yaml` |
| DELETE | `/problems/{id}` | 消す |

- 答えは, 読んで答えて書く間を鍵で 1 つずつにする (同時の答えが消えないように)
- 識別子は 12 桁の 16 進. 形の違う識別子は置き場の外を指せないように 404
- 置き場の壊れたファイル (YAML として読めない, 版が無い, 形が崩れて確かめが落ちる) は, 一覧に「読めない」印で出し (一覧全体は止めない), 開くと 422 で理由を返し, 消せる (消すときは中身を読まない)
- 画面から受け取る場所 (取り込み, 列の読み込み, 書き出し) は絶対パスだけ (起動した場所で意味が変わらないように). 手元のファイルの誤りは日本語の文にする
- 骨組みの書き出しは, 書く前に書けるかを全て確かめる (ML-Quest. 一部だけが残らないように)
- 書き出せるか (`exportable`) は ML-Quest の `project_error` が `None` かだけで決める (受け渡しの値を作れるかは条件にしない. 「直す」が残っていても骨組みを組めれば, 確かめた上で書き出せるため). `export_error` はその文 (組めない理由)
- `open_errors` は ML-Quest の `open_errors` (骨組みを組める確かめの `error` と, 入れたデータの確かめの `error`. 項目は確かめと同じ `level`, `id`, `message`) で, 書き出せるときだけ求める (書き出せなければ空. 重いデータの分析をしないため). データの分析は `/insight` と同じ覚えた結果を渡し (無ければ求めて覚える), 詳しい画面だけで返す (一覧は分析しない). 覚える鍵を ML-Quest が覚えた結果を確かめる印と同じにするので, `/insight` と `open_errors` が食い違わず, ML-Quest が求め直すこともない (書き出しの記録を保存した後も同じ鍵). データの場所が文字列でない (手で書いたファイルの取り込みなど) 場合は, ML-Quest の確かめが形の `error` (`data.source`. 骨組みを組めないので書き出しは 400) にし, データの分析も同じ `error` を返す (画面の側では確かめない. 決まりを ML-Quest だけが持つように). 画面は問題の設定の確かめとデータの確かめを並べるときに, 同じ確かめ (重さ, 場所, 文が同じ) を 1 つにする. 場所を調べる権限が無く分析か印が `OSError` になる場合は, 「データを読めません: …」の `error` にしてログに残す. 詳しい画面と `/insight` を止めず, 直すところには問題の設定の確かめの `error` と並べる. 他の例外は受け止めない (ML-Quest の不具合を読めないデータに見せないため) データを入れている問題の設定では, 答えを変えた応答がデータの分析を待つ (続く `/insight` は覚えた結果を返す)
- 書き出しは, 組めるときだけ重いデータの分析を保存の鍵の外で先に求めて覚え (他の保存を長く止めないように), 鍵の中では覚えた結果を使う (間に答えかデータが変わっていれば鍵の中で求め直す). 組めなければ分析せずに 400
- 書き出しの 409 の `detail` は `{"message": 画面の文, "open_errors": 一覧}`. ML-Quest の誤りの文 (ライブラリを使うコード向けの `accept_errors=True` の案内) は返さない. 書き出しの前に一覧を求め直すので, 画面が古い一覧で確かめていても, 残っていれば 409 か, 指定があれば今の一覧を README に残して書き出す

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| 問題の設定 | 課題から機械学習の受け持ちまでの答えをまとめたもの. `problem.yaml` (ML-Quest の形) |
| 節 | 問いのまとまり. 課題から運用までの 10 の節 |
| 確かめ | 答えどうしの食い違いと足りない答え. 重さは「直す」「見直す」「知らせ」 |
| 筋道 | 課題から行動までの要約の文 |
| 後ろの段階に渡す値 | ML-Quest の受け渡し (`handoff`). データの分析から推論までの段階が使う値 |
| 列の予測 | 受け持ちが予測する (`predict`) で, 正解の種類が表の列 (`column`) のもの |
| 骨組み | 書き出す ML-Found のプロジェクト (config, `train.py`, README, `problem.yaml` の写し). 写しは置き場の元の問題の設定の場所 (`origin`) を持つ (推論の段階が元を読み, 後で直した損得を使うため) |

## 6. 置き場

既定は `~/.ml-pathfinder/` (環境変数 `ML_PATHFINDER_HOME`).

- `problems/<識別子>/problem.yaml`: 問題の設定 (ML-Quest の形. 一時ファイルに書いてから置き換える)
- `problems/<識別子>/data/<写しごとの名前>/`: 入れたデータの写し. 入れるたびに別のサブディレクトリに写し (入れ直したファイルが読めなくても今の写しが残る), 写し終えたとき (失敗も含む) に, 写している途中の他の入れ直しが無ければ, 今の写し以外の写しを片付ける (写しの名前の形は ML-Quest と同じ). 写すのは鍵の外 (大きなデータでも他の保存を止めない). 鍵の中で, 写している間に問題の設定が消されていれば 404 (写しで作り直されたディレクトリも片付ける), 外されたか別のデータが入れられて写しが消えていれば 409 にする. 外すとき, 片付けるとき, 問題の設定を消すときは, 鍵の中で `.removing-...` に名前を変えるだけにし, 消すのは鍵の外 (消し損ねたものは次の片付けで消す). 書き出した `problem.yaml` は `data.origin` に元の場所を持つので, 置き場の写しが消えても元の場所から読める

## 7. 安全

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

- 識別子の形と, 画面から受け取る場所 (絶対パスだけ) を確かめる (上の「4. API」)
- 置き場の写しと元のデータを分け, 元のデータは書き換えない (上の「6. 置き場」)

## 8. 課題の型への広げ方

課題の型の分け方と広げる順は ML-Quest の docs/DESIGN.md の「課題の型への広げ方」. 問題の設定の問いと選択肢を広げるのは ML-Quest で, この画面はそれを描く. 版 2 の型に依らない問いと型ごとに分かれる問い, 守る指標と使い道と後段の問いは描ける (上の「3. 画面」). 意思決定の型と欄, タスクの名前は ML-Quest が返すもので描く. 節の数 (10) は画面が持つ.
