# ML-Pathfinder 操作ガイド

ML-Pathfinder の使い方を画面の順にまとめる. 導入と起動はリポジトリのルートの [README](../README.md), 設計の方針と API は [DESIGN.md](DESIGN.md) を参照.

## 1. 問題の設定を作る

一覧の画面 (「問題の設定」) で, 次のどれかで始める.

- **新しく作る**: 課題の言葉で名前を書いて「作る」
- **見本を開く**: 架空の課題で答えを埋めた見本の写しが開く (元の見本は変わらない). 見本は 3 つ
    - 総菜の作る量: 翌日の品ごとの売れる数を予測し, 量を決める (時系列の予測)
    - 解約の引き止め: 来月に解約するかを予測し, 連絡する会員を選ぶ (分類)
    - 問い合わせの振り分け (機械学習を使わない): 受付で種類を聞けば足りると分かり, 機械学習を使わないで終える
- **ファイルから取り込む**: 書き出した `problem.yaml` (かそれを持つディレクトリ) を写して取り込む. 元のファイルは書き換えない

一覧には, 答えた要る問いの数と直すところの数, 後ろの段階に渡せるか, 機械学習を使わないで終えたかが出る.

## 2. 問いに答える

問題の設定の画面で, 左の節を 1 から順に選び, 問いに答える. 節は次の 10.

1. 課題, 2. 解けたと言える指標, 3. 課題の分解, 4. 決めること, 5. 機械学習の受け持ち, 6. 予測の時点で使える情報, 7. 損得と制約, 8. 学習で見る指標, 9. 効果の確かめ方, 10. 運用

- 文と数は欄を離れたとき, 選択肢は選んだときに保存される. 要因と打てる手, 損得と制約は「保存」を押す
- 前の答えで要らなくなった問い (タスクを回帰にした後の時刻の列など) は出ず, 古い答えは使わない
- 5 の節では, 受け持ち (予測する, 作る, 並べる, まとめる, 効果を見積もる), 1 件の単位, 出力の形, 正解の出どころ, 作り方, 正解の種類を問う. 目的の列やタスクの問いは, 予測するで正解の種類が表の列のときだけ出る
- 5 の節で「機械学習を使いますか」に「いいえ」と答えると, そこで終える (後ろの段階に渡すものは無い)

## 3. 手元のデータを入れる

5 の「手元のデータは」でデータを入れると (ML-Fathom と同じ読み込み. データは問題の設定の置き場に写す), 列の名前が入り, 後の問いの下に答えの候補 (目的の列, 時刻の列, 漏れの疑いのある列, ID のような列など) が出る. 押すと答えになる.

- 7 の「今のやり方をデータで書くと」に答えると, 今のやり方の損がデータから求まり, 2 の「今の値は」の候補にも出る
- 「使えるデータの列は」は, データを入れずに「データのファイルから読む」で 1 行目だけを読むこともできる
- 画像の領域や点群を予測する場合は, ML-EDA が書き出したデータセットのディレクトリ (`dataset.yaml` を持つ. 選ぶ対話で「データセット」の印が付く) を入れる. 表でないので列は入らず, 件数と正解の種類, 合わない理由が問いの下の確かめに出る

## 4. 確かめ, 筋道, 後ろの段階に渡す値

右の欄で, 課題から行動までの筋道, 確かめ (直す, 見直す, 知らせ), 後ろの段階に渡す値を見る. 確かめの「n へ」で, その問いの節に移る.

後ろの段階に渡す値は, 列の予測なら目的の列, タスク, 分割, 使う列と除く列, 意思決定. 列の予測でなければ, 受け持ち, 1 件の単位, 出力の形, 正解の種類と出どころ, 作り方, 監視する指標, 入れたデータの場所.

強化学習やシミュレータなど, 学習の段階で別に入れるものが要る答えでは, 画面の上の方に「学習の段階の準備」のカードが出る (答えを止めない).

## 5. 学習のプロジェクトを書き出す

直すところが無くなると「学習のプロジェクトを書き出す」を押せる. 書き出すディレクトリを選ぶと, config, `train.py`, README, `problem.yaml` の写しが書かれる. 既にあるファイルは, 上書きを選んだときだけ上書きする.

- 書き出せるのは, 列の予測と, 予測するで正解の種類が画像の領域か点群のもの (最良を選ぶ指標がその他でないとき). 書き出せない理由はボタンの下に出る
- 領域と点群は, 入れたデータセットを骨組みの `data/` に写す (入れていなければ README で ML-EDA の書き出しを案内する). 推論の一式はまだ作らない
- 書き出した README の「次にすること」の順に, データセット (ML-Fathom) とモデルの定義 (ML-CreateArchitecture) を置いて学習 (ML-Found, ML-Dashboard) し, 実験の中の推論の一式を ML-Provide に登録する. ML-Provide で一式に問題の設定をつなぐと, 7 の損得が推論の意思決定の既定になる

「problem.yaml」のボタンで, 問題の設定のファイルを保存する.

## 6. 他のアプリとの共有

開いている問題の設定のファイルを他のアプリ (ML-Fathom の「問題の設定に書き戻す」など) が書き換えると, 画面に戻ったときか 10 秒以内に読み直す. 外で変わった問いの書きかけは, 外の値に置き換わる.

画面は API を使って動くが, API は画面のためのもので, スクリプトから問題を設定する場合は ML-Quest を直接使う.

## 7. 置き場

既定は `~/.ml-pathfinder/` (環境変数 `ML_PATHFINDER_HOME` で変えられる). 問題の設定は `problems/<識別子>/problem.yaml` に, 入れたデータの写しは `problems/<識別子>/data/` に置く.
