## 準備

この手順書でよく使う言葉.

| 言葉 | 意味 |
| --- | --- |
| 問題 | 課題から機械学習の受け持ちまでの答えをまとめたもの. `problem.yaml` に保存する |
| 節 | 問いのまとまり. 課題から運用までの 10 の節 |
| 確かめ | 答えどうしの食い違いと足りない答え. 重さは「直す」「見直す」「知らせ」 |
| 後ろの段階に渡す値 | データの分析, モデルの作成・選定, 学習・評価, 推論の各段階で使う値 |
| 骨組み | 書き出す学習のプロジェクト (config, `train.py`, README, `problem.yaml` の写し) |

始める前に, ML-Pathfinder を README の「導入と起動」の手順で導入しておく (`make setup`).

## 1. 起動する

ML-Pathfinder はローカルで動く Web アプリ. 端末で起動して, 表示された URL をブラウザで開く.

1. ML-Pathfinder を clone したディレクトリで `make serve` を実行する. 画面をビルドしてから `http://127.0.0.1:8770` で待ち受ける. 端末は使ったままになるので, 止めるまでそのままにする
2. 端末に `ML-Pathfinder を開く: http://127.0.0.1:8770/api/auth?token=…` と出るので, その URL を開く. トークンは起動するたびに変わる
3. 「問題の設定」の一覧の画面が開けば準備完了

```bash
make serve
```

> **トークンを毎回同じにする**
> `ML_PATHFINDER_TOKEN=好きな文字列 make serve` で起動すると, `http://127.0.0.1:8770/api/auth?token=好きな文字列` を開けば入れる.

## 2. 問題を作る

一覧の画面 (「問題の設定」) で, 次のどれかで始める.

- **新しく作る**: 課題の言葉で名前を書いて「作る」
- **見本を開く**: 架空の課題で答えを埋めた見本の写しが開く (元の見本は変わらない). 同じ名前の問題が一覧に既にあれば, 「解約の引き止め (2)」のように番号を付けた名前になる. 見本は 6 つ
    - 総菜の作る量: 翌日の品ごとの売れる数を予測し, 量を決める (時系列の予測)
    - 解約の引き止め: 来月に解約するかを予測し, 連絡する会員を選ぶ (分類)
    - 写真の仕分け (既製のモデル): 届く写真の名前の候補を既製のモデルで付け, 学習せずに推論の一式を作る
    - 商品の写真の群分け (既製の埋め込み): 既製のモデルの埋め込みで, 見た目の似た商品の写真を群にまとめる (学習しない)
    - 似た商品の写真を探す (既製の埋め込み): 既製のモデルの埋め込みで, 届いた写真に見た目の近い商品の写真を上位 K 件探す (学習しない)
    - 問い合わせの振り分け (機械学習を使わない): 受付で種類を聞けば足りると分かり, 機械学習を使わないで終える
- **ファイルから取り込む**: 書き出した `problem.yaml` (かそれを持つディレクトリ) を写して取り込む. 元のファイルは書き換えない

一覧には, 答えた要る問いの数と直すところの数, 後ろの段階に渡せるか, 機械学習を使わないで終えたかが出る.

## 3. 問いに答える

問題の画面で, 左の節を 1 から順に選び, 問いに答える. 節は次の 10.

1. 課題, 2. 解けたと言える指標, 3. 課題の分解, 4. 決めること, 5. 機械学習の受け持ち, 6. 予測の時点で使える情報, 7. 損得と制約, 8. 学習で見る指標, 9. 効果の確かめ方, 10. 運用

- 文と数は欄を離れたとき, 選択肢は選んだときに保存される. 要因と打てる手, 損得と制約は「保存」を押す
- 数の並びの問い (学ぶ分位点の水準など) は, 数を半角のカンマで区切って書く (例: `0.1, 0.5, 0.9`). 末尾のカンマや続いたカンマ (`0.1,,0.9`) があると, 欄の下に「空の要素があります」と出て保存しない (書いた文は残るので, 直して欄を離れる). 読点 (、) や全角のカンマでは区切れない. 空にすると答えを消す
- 前の答えで要らなくなった問い (タスクを回帰にした後の時刻の列など) は出ず, 古い答えは使わない
- 5 の節では, 受け持ち (予測する, 作る, 並べる, まとめる, 効果を見積もる), 1 件の単位, 出力の形, 正解の出どころ, 作り方, 正解の種類を問う. 目的の列やタスクの問いは, 予測するで正解の種類が表の列のときだけ出る
- 並べるでは (既製のモデルをそのまま使う答えの他), 反応の表 (1 行が 1 つの反応. 利用者が品物を買った, 見たなど) の利用者の列, 品物の列, 反応の時刻の列, 反応の強さの列 (任意. 0 より大きい行だけを反応とみなす), 見せただけの印の列 (任意. 見せたが選ばれなかった品物の行に真を付けた列. あれば見せただけの品物を学習の負の例にし, 1 回の提示の中で選んだ品物を上に並べられたかも確かめる), 提示の列 (任意. 見せただけの印の列を答えたときだけ. 1 度に見せた品物の並びの ID. 無ければ同じ利用者と時刻の行を 1 回の提示とみなす) と, 利用者ごとに上位何件を並べるか (K. Recall@K と NDCG もこの K で数える) を問う. 列は 4 章で反応の表を入れると, その列から選べる
- まとめるでは (既製のモデルをそのまま使う答えの他), 1 行が 1 つの対象 (顧客など) の表の, 群を作るのに使う列 (複数. ID や名前のように行ごとに違う列は入れない), 行を見分ける列 (任意. 群の割り当ての表に書く), いくつの群に分けるか (2 以上), 群の安定性をどう作り直して数えるか (種を変えるか, 行の 8 割を引き直す) を問う. 2 の節の守る指標の問いは出ない (群は人が解釈して使い, 使われたかは運用の後に見るため). 8 の最も良いモデルを選ぶ指標には「群のまとまり」が出る
- 予測するで正解の種類を「異常か正常か」にすると (正常の行が多い表. 機械のセンサの値や取引の記録など), 正解の出どころは「無い」か「少し」を選ぶ. 5 の節で, 異常の正解の列 (少しのときだけ. 異常は 1, 正常は 0 か空), 行の id の列 (任意. 人が確かめた結果の記録が 1 行を指す), 異常の度合いを出すのに使う列 (複数), 度合いの決め方 (正常の行だけで学ぶ自己符号化器か, 正常の行の中心からの距離) を問い, 7 の節で人が 1 回に確かめられる件数の上限 (守る指標) を問う. 度合いは確率でないので, 7 の損得と今のやり方は問わない. 8 の最も良いモデルを選ぶ指標は, 自己符号化器で正解が少しなら「度合いの順の異常の当たり (PR-AUC)」と上位 K 件の適合率と損失, 正解が無ければ損失だけで, 距離では問わない (学習しない)
- 効果を見積もるで「続けて自分で行動を選びますか (方策)」に「いいえ」と答え, 集め方を「今ある記録から」にすると, 過去に行動した記録の表 (クーポンを配ったかと, その後に買ったか) から顧客ごとの効果 (配ったときの結果 − 配らないときの結果) を見積もる. 処置は無作為に配った記録を前提にする (配る相手を選んだ記録では効果を取り違える). 正解の出どころは「介入の記録」を選ぶ. 5 の節で, 処置の列 (配ったら 1, 配らなければ 0), 結果の列, 結果の種類 (起きたか (0 と 1. 効果は確率の差) か量 (買った額. 効果は値の差)), 行の id の列 (任意. 行ごとの効果と配る判断が 1 行を指す), 効果の見積もりに使う列 (複数. 配る前に分かっている顧客の特徴. 配った後に決まる列は入れない), 効果の決め方 (任意. 処置の群と対照の群で 2 つの予測を別々に学ぶ T-learner (既定) か, 処置の列を入力の終わりに足して 1 つの予測で学ぶ S-learner) を問う. 7 の「行動の損得と制約は」の型は「効果の上位から配る」だけで, 配る数の上限 (守る指標. 1 回に配れる数) を書く. 損得の値と今のやり方は問わず, 値を決める手伝いも出ない. 8 の最も良いモデルを選ぶ指標は「効果の順の当たり (Qini 係数)」か損失で, 評価で見る上位の割合 K (0 より大きく 1 以下. 3 割に配れるなら 0.3) を問う
- 続けて「記録で変えたのは, 配ったかですか, 値段ですか」に「値段」と答えると (答えなければ配ったか), 試しに値段を上げ下げした売れ行きの記録の表から, 値段を入れて売れた数を予測し, 商品ごとに利益が最も大きい値段を選ぶ (値段を変える判断). 値段は試しに変えた記録 (無作為に近い) を前提にする (売れ行きに合わせて値段を決めた記録では, 値段の効き方を取り違える). 5 の節で, 値段の列 (売ったときの値段. 0 より大きい数), 売れた数の列 (その値段で売れた数. 予測する値), 原価の列 (任意. 商品 1 つを仕入れるか作るのにかかる値段. 利益は (値段 − 原価) × 売れた数. 無ければ売上で選ぶ), 商品の id の列 (任意. 値段を選ぶ単位. 無ければ行ごと), 行の id の列 (任意), 売れ行きの予測に使う列 (複数. 値段を決める前に分かっている商品の特徴. 値段の列と, 売れた後に決まる列は入れない) を問う. 今の値段は列で持たず, 商品の id の列があれば商品ごとの記録の値段の中央値, 無ければその行の値段にする. 7 の「行動の損得と制約は」の型は「利益が最も大きい値段を選ぶ」だけで, 値段の候補 (今の値段に対する変える割合を小数でカンマで区切って並べる. 0.1 は 10 %. 0 (今の値段) を含める. 例: `-0.1, -0.05, 0, 0.05, 0.1`) と, 値段を変える幅の上限 (守る指標. 変える割合の絶対値. 1 割までなら 0.1. 上限を超える候補は選ばない) を書く. 損得の値と今のやり方は問わず, 値を決める手伝いも出ない. 8 の最も良いモデルを選ぶ指標は売れた数の「外れの大きさの平均 (平均絶対誤差)」か損失
- 予測するで正解の種類を「先の期間の需要」にすると (既製のモデルをそのまま使う答えの他), 商品ごとの日ごとの売れた数の記録の表から, 先の決めた期間の需要 (売れる数の合計) を分位点で予測し, 商品ごとに発注の数を決める (時間をまたぐ量の判断). 出力の形は「分布」, 正解の出どころは「データの列」を選ぶ. 5 の節で, 商品の id の列 (発注の数を決める単位), 日付の列 (日ごと), 日ごとの売れた数の列 (売れなかった日は 0 の行を書く), 在庫の数の列 (任意. その日の始めの在庫. 無ければ在庫を 0 として発注する), 行の id の列 (任意), 需要の予測に使う商品の特徴の列 (任意. 複数. 過去の売れた数と曜日はデータの分析で列にするので入れない), 先の期間の日数 (任意. 発注してから次の発注で届くまでの日数. 無ければ 7 日), 学ぶ分位点の水準 (任意. 0 より大きく 1 より小さい数をカンマで区切って並べる. 無ければ 0.1, 0.25, 0.5, 0.75, 0.9) を問う. 7 の「行動の損得と制約は」の型は「損の比で発注の数を決める」だけで, 1 つ足りないときの損 (品切れの損. 売り逃した利益など), 1 つ余ったときの損 (売れ残りの損. 捨てる原価か持ち越す費用) と発注の数の上限 (守る指標. 置き場所の上限) を書く. 2 つの損は商品 1 つあたりの同じお金の単位の正の数で書く. 発注に使う水準 τ は品切れの損 / (品切れの損 + 売れ残りの損) で決まり (3 と 1 なら 0.75), 学ぶ水準に答えが無くても 0.5 と一緒に足される. 損得の値と今のやり方は問わず, 値を決める手伝いも出ない. 8 の最も良いモデルを選ぶ指標は分位点の損失か, 0.5 の分位点の「外れの大きさの平均 (平均絶対誤差)」
- 7 の節では, 2 の節で守る指標を書き, 列の予測で量を決めるか対象を選ぶか振り分ける意思決定なら (対象を選ぶで効果を確率の差で渡すときの他), 「守る指標は, たどり直しで数えられる量のどれに当たりますか」が出る. 選択肢は意思決定の型で数えられる量 (足りなかった行の割合, 選んだ件数, 見逃した件数など) と「指さない」. 割合の量を選んだら, 2 の守る線は 0 から 1 で書く (5 % なら 0.05)
- 5 の節で「機械学習を使いますか」に「いいえ」と答えると, そこで終える (後ろの段階に渡すものは無い)
- 7 の「行動の損得と制約は」の値に自信が無ければ, 下の「値を決める手伝い」を開く. 保存した値のうち, 結論を変える項目 (量を決めるなら足りないときと余ったときの損, 対象を選ぶなら価値, 費用, 効果, 件数か費用の上限, 振り分けるなら見逃しと空振りの損, 回せる件数) ごとに幅の下と上を書き, 点の数を選んで「求める」を押す. 値を 1 つずつ幅の中で変えたとき (他の値は保存した値のまま) の, 決め方の値 (置く分位点の水準, 得になる確率の下限, 回す確率のしきい値) と件数の上限の表が, 結論を大きく変える項目から順に出る. 幅を書いた項目が 2 つ以上で, 先頭の振れ幅が 0 より大きければ, 先頭の項目に「決め手」の印が付く. データ (4 章) と 7 の今のやり方があれば, 量を決めると振り分けるでは, データの上の今のやり方の損と, 振り分けるでは最も損の小さいやり方 (今のやり方, どれも回さない, 全てを回す) も出る. 行動の件数と量そのものは予測が要るので出ない (学習の後に推論の段階で確かめる). 列で書いた値には幅を渡せない. データを読むので, 大きなデータでは少し待つ

## 4. 手元のデータを入れる

5 の「手元のデータは」でデータを入れると (データの分析の段階と同じ読み込み. データは問題の設定の置き場に写す), 列の名前が入り, 後の問いの下に答えの候補 (目的の列, 時刻の列, 漏れの疑いのある列, ID のような列など) が出る. 押すと答えになる.

- 7 の「今のやり方をデータで書くと」に答えると, 今のやり方の損がデータから求まり, 2 の「今の値は」の候補にも出る
- 「使えるデータの列は」は, データを入れずに「データのファイルから読む」で 1 行目だけを読むこともできる
- 画像の領域や点群を予測する場合は, データの分析の段階が書き出したデータセットのディレクトリ (`dataset.yaml` を持つ. 選ぶ対話で「データセット」の印が付く) を入れる. 表でないので列は入らず, 件数と正解の種類, 合わない理由が問いの下の確かめに出る

## 5. 確かめ, 筋道, 後ろの段階に渡す値

右の欄で, 課題から行動までの筋道, 確かめ (直す, 見直す, 知らせ), 後ろの段階に渡す値を見る. 確かめの「n へ」で, その問いの節に移る.

後ろの段階に渡す値は, 列の予測なら目的の列, タスク, 分割, 使う列と除く列, 意思決定. 列の予測でなければ, 受け持ち, 1 件の単位, 出力の形, 正解の種類と出どころ, 作り方, 入れたデータの場所. どちらも, モデルの作成・選定の欄に「モデルの作成・選定の雛形」として受け持ちに合う雛形 (モデルの作成・選定の段階で開ける例の名前. 例えば点群の予測を一から学習するなら `point_cloud_predictor`, 表の生成なら `diffusion_denoiser`, 並べるなら `two_tower_retrieval`) を, 学習の欄に監視する指標 (何を測るかの言葉を添える) と監視の向き (`min` は小さいほど良い, `max` は大きいほど良い) を出す (既製のモデルをそのまま使う答えでは出ない). 一から学習するのに合う雛形が無ければ「受け持ちに合う雛形はありません」と出るので, モデルの作成・選定の段階で定義を選ぶ. 一から学習しない作り方では「一から学習しないので, 合う雛形はありません」と出る. 学習のプロジェクトを書き出した後は, その場所 (6 章) も出る.

並べるでは「並べ方」の欄に, 利用者ごとに上位何件を並べるか (K) と, 答えた列と役割 (利用者ごとに品物を並べる, 並べる品物, 古い反応で学び新しい反応で確かめる, 0 より大きい行だけを反応とみなす, 見せただけの品物を学習の負の例にする, 同じ利用者と提示の行を 1 回の提示とみなす) が出る. 分割は反応の時刻の列の順.

まとめるでは「まとめ方」の欄に, 群の数, 群を作る列, 行を見分ける列, 群の安定性の数え方 (選んだ選択肢の言葉) と, 評価が群の安定性 (作り直した群と元の群の一致) と群の要約 (群ごとの行の数, 割合, 安定性と列の平均か最も多い値) であることが出る. 分割は無作為. 守る指標は問わないので推論の欄に守る指標は出ない.

異常の検知では, データの分析の欄に異常の正解の列 (無ければ全ての行を正常と見なす), 行の id の列, 度合いに使う列が出て, 「異常の度合い」の欄に度合いの決め方 (選んだ選択肢の言葉), 人が 1 回に確かめる件数の上限と評価の上位 K 件の K (件数の上限と同じ) が出る. 評価は, 正解が少しなら上位 K 件の適合率と PR-AUC, 無ければ度合いの分布と上位 K 行の要約 (行の id, 度合い, 最も外れた列) で見る. 距離ではモデルの作成・選定と学習・評価の欄は出ない. 推論の欄には, 度合いの高い順に件数の上限まで人の確かめに回す振り分けと, 学習の後に異常の度合いの一式を作ることが出る.

効果の見積もりでは, データの分析の欄に処置の列, 結果の列と結果の種類, 行の id の列, 見積もりに使う列と除く列が出る. 分割は層別で, 全ての分割に処置の群と対照の群が入り, 結果の欠けた行は落とす. 「効果の見積もり」の欄に, 効果の意味 (確率の差か値の差), 評価の上位 K 割の K と配る数の上限が出る. 顧客ごとの正解の効果は見えないので, 評価は効果の見積もりの高い順の Qini の曲線と Qini の係数, 上位 K 割の効果の差 (処置の群と対照の群の結果の平均の差) で見る. 「効果の見積もり」の欄には効果の決め方 (T-learner か S-learner) も出る. モデルの作成・選定の欄には雛形 `tabular_uplift` と, 出力が処置したときの予測 `treated` としないときの予測 `control` の 2 つであることが出る (S-learner では雛形 `tabular_uplift_s` と, 出力が結果の予測 `outcome` の 1 つで, 処置の列を入力の終わりに足すので入力の幅が見積もりに使う列の数 + 1 であることが出る). 推論の欄には, 効果の高い順に配る数の上限まで配る判断と, 学習の後に推論の段階が読む効果の決め方 (`uplift_estimator.json`) と行ごとの効果 (`uplift_effects.csv`) が実験に残り, 効果の推論の一式を実験の `inference/` に作ることが出る (仮のモデルでは作らない. S-learner では, 処置の列を入力の終わりに足した 1 つの予測の一式であることも出る).

値段を変える判断では, データの分析の欄に値段, 売れた数, 原価, 商品の id, 行の id の列 (無い列は「無し」と出し, 代わりの扱いも添える), 予測に使う列と除く列が出る. 分割は層別で, 値段の段 (値段の高さで行を分けた組) で層を作り, 売れた数の欠けた行は落とす. 「値段の選び方」の欄に, 今の値段の決め方, 値段の候補 (+5 % のような割合で), 値段を変える幅の上限と, 利益の数え方 ((値段 − 原価) × 予測した売れた数) が出る. 評価は, 記録の値段での売れた数の誤差, 弾力性 (値段を 1 % 上げたときに売れた数が何 % 変わるか) と, 選んだ値段と今の値段での見込みの利益の比べで見る. モデルの作成・選定の欄には雛形 `tabular_price` と, 入力の最後の列が値段で, 出力が売れた数の予測 `units` であることが出る. 後ろの段階に渡す値では, 値段の候補と上限を % で出す. 推論の欄には, 商品ごとに上限の中で利益が最も大きい値段を選ぶ判断と, 学習の後に推論の段階が読む値段の決め方 (`price_estimator.json`) と商品ごとの選んだ値段 (`price_choices.csv`) が実験に残り, ML-Inference の値段の一式が実験の `inference/` にできることが出る. 選ぶ値段は見積もりなので, 値段を変えた効き目は値段を試して確かめる.

時間をまたぐ量の判断では, データの分析の欄に商品の id, 日付, 日ごとの売れた数, 在庫の数, 行の id の列 (無い列は「無し」と出し, 代わりの扱いも添える), 予測に使う商品の特徴の列と除く列が出る. 分割は時刻の順で, 発注を決める日の順に分け, 先の期間の合計が分からない行 (記録の終わりの近く) は学習と評価に使わない. 「発注の数の決め方」の欄に, 先の期間の日数, 学ぶ分位点の水準 (0.5 と, 損を決めていれば τ を足したもの), 発注に使う水準 τ (損を決めると値が出る) と, 発注の数が τ の分位点から在庫の数を引いた数の切り捨てと切り上げ (0 より下は 0) のうち見込みの損の小さい方 (同じなら少ない方) を上限で切ったものであることが出る. 評価は, 0.5 の分位点の誤差, 分位点の損失と, 実際の需要での発注の数の損 (前の期間と同じ数を発注した損との比べ) で見る. モデルの作成・選定の欄には雛形 `tabular_demand` と, 出力が水準の小さい順の分位点 `quantiles` (大きさは学ぶ水準の数) であることが出る. 推論の欄には, 損と上限と τ の発注の判断と, 学習の後に推論の段階が読む需要の決め方 (`demand_estimator.json`) と発注の数 (`demand_orders.csv`) が実験に残り, ML-Inference の需要の一式が実験の `inference/` にできることが出る. 発注の数は見積もりで, 品切れの日の売れた数は需要より少ないので, 品切れの多い商品の需要は少なめに見積もられる. 実際の損は発注の後の売れた数で確かめる

列の予測で守る指標を書いていれば, 推論の欄に守る指標の名前, 向き, 守る線と, 7 で選んだたどり直しで数える量が言葉 (「選んだ件数」など) で出る.

強化学習やシミュレータなど, 学習・評価の段階で別に入れるものが要る答えでは, 画面の上の方に「学習・評価の段階の準備」のカードが出る (答えを止めない).

5 の節で, 効果を見積もるで方策 (続けて自分で行動を選ぶ) と答え, 集め方が今ある記録でなければ,「Gymnasium の環境の登録名は (あれば)」を問う (任意. `CartPole-v1`, `Hopper-v5` など). 答えた登録名は後ろの段階に渡す値の「方策を学ぶ環境」に出て, 学習・評価の段階に渡る. 実機とのつなぎや自作のシミュレータなど, 登録名の無い環境なら空のままにする. そのときは「方策を学ぶ環境」に自作の環境と出て, 骨組みには自作の環境の雛形 `env.py` を書き出す (中身は自分で書く). 答えていれば, 骨組みの config の `env.id` にその登録名を書く.

## 6. 学習のプロジェクトを書き出す

骨組みを組める答えがそろうと (機械学習を使うと決め, 受け持ち, 目的の列, タスク, 指標などに「直す」が無くなると)「学習のプロジェクトを書き出す」を押せる. 書き出すディレクトリを選ぶと, config, `train.py`, README, `problem.yaml` の写しが書かれる. 既にあるファイルは, 上書きを選んだときだけ上書きする.

- 書き出せるのは, 列の予測と, 予測するで正解の種類が画像の領域か点群のもの (最良を選ぶ指標がその他でないとき) と, 作るで正解の種類と出力の形が画像のもの (条件の無い画像の生成. 最良を選ぶ指標が損失のとき) と, 作るで正解の種類と出力の形が表のもの (条件の無い表の生成. 最良を選ぶ指標が損失か列ごとの分布の近さで, 入れたデータがあれば表のとき (入れていなくてもよい)) と, 並べるで出力の形が順位のもの (既製のモデルをそのまま使わず, 入れたデータがあれば表のとき (入れていなくてもよい)) と, まとめるで出力の形が群のもの (既製のモデルをそのまま使わず, 入れたデータがあれば表のとき (入れていなくてもよい)) と, 異常の検知で出力の形が値のもの (入れたデータがあれば表のとき (入れていなくてもよい)) と, 効果を見積もるで方策でなく集め方が今ある記録のもの (効果の見積もり. 出力の形が行動ごとの差で, 最良を選ぶ指標が Qini の係数か損失で, 入れたデータがあれば表のとき (入れていなくてもよい)) と, 効果を見積もるで方策でなく集め方が今ある記録で, 記録で変えたものが値段のもの (値段を変える判断. 出力の形が行動ごとの差で, 最良を選ぶ指標が売れた数の平均絶対誤差か損失で, 入れたデータがあれば表のとき (入れていなくてもよい)) と, 予測するで正解の種類が先の期間の需要のもの (時間をまたぐ量の判断. 出力の形が分布で, 最良を選ぶ指標が分位点の損失か 0.5 の分位点の平均絶対誤差で, 入れたデータがあれば表のとき (入れていなくてもよい)) と, 効果を見積もるで方策と答えたもの (集め方が今ある記録でなく, 最良を選ぶ指標が報酬か損失のとき. 報酬なら監視は `valid/reward` を大きく, 損失なら `valid/loss` を小さく見る). 書き出せない理由はボタンの下に出る
- 骨組みを組めても, 課題の文, 損得と制約, 入れたデータの確かめなどに「直す」が残っていれば, ボタンの下にその数が出る. 押すと書き出す対話に「直す」の一覧が出て, 「それでも書き出す」を選ぶまで書き出せない. 残ったまま書き出すと, 書き出した README の最後に一覧が残る. 問題の確かめの「直す」が残るなら, 推論の段階に渡す値を作れないので, 直すまで問題につなげない. 入れたデータの確かめの「直す」だけなら, 渡す値は作れるが, 同じ誤りのまま使われないように直すまでつながない. 列の予測で損得と制約に「直す」が残るなら, 推論の一式に意思決定の既定値は付かない. 効果の見積もりで損得と制約に「直す」が残るなら, 配る数の上限を付けずに (config の `uplift.budget` を空にして) 書き出す. 値段を変える判断で損得と制約に「直す」が残るなら, 値段の候補と変える幅の上限を付けずに (config の `price.candidates` と `price.max_change` を空にして) 書き出す (空のままでは学習の前に止まる). 時間をまたぐ量の判断で損得と制約に「直す」が残るなら, 発注の判断の損と上限を付けずに (config の `order` を空にして) 書き出す (空のままでは学習の前に止まる). どの場合も, 学習して実験の中にできた `inference/` は推論の段階で登録できる (問題にはつながない). 直してから書き出し直すのを勧める
- 入れたデータが画像, 文か音声 (列の予測), または画像の領域か点群の場合は, 今のやり方と同じ件では比べない. 8 の「今のやり方 (人の目視や今の仕組み) で, 正解率は幾つですか」(「正解率」の所は選んだ指標の名前. IoU, Chamfer 距離など) に答えておくと, 学習のスクリプトはテスト用の分割のモデルの値と答えた値を評価の表 (`evaluations/baseline_test.json`) に並べる (別のデータで数えた値との比べなので目安). 答えていなければ並べず, README と `train.log` にそう書く
- 領域と点群は, 入れたデータセットを骨組みの `data/` に写す (入れていなければ README で ML-EDA の書き出しを案内する). `models/model.yaml` に定義を置いて学習すると, 実験の中の `inference/` に推論の一式を作る (仮のモデルでは作らない)
- 画像の生成は, 入れた画像のディレクトリを骨組みの `data/` に写し, 拡散のモデルを学んで損失と作った画像の見本で評価する (今のやり方とは比べないので, 8 の今のやり方での値の問いは出ない). `models/model.yaml` に定義を置いて学習すると, 実験の中の `inference/` に件数と種で画像を作る推論の一式を作る
- 表の生成は, 8 の「最も良いモデルを何で選びますか」で「作った表と本物の表の列ごとの分布の近さ」(数の列と種類の列ごとに, 作った表と本物の表の値の散らばりがどれだけ近いかの平均. 小さいほど良い) を選べる (監視は `valid/column_distance` を小さく見る). 入れた表のファイルを骨組みの `data/` に写し, 拡散のモデルを学んで列ごとの分布の近さと作った表の見本で評価する (今のやり方とは比べない). 書き出した列を全て作るので, ID のような列と作らない列はデータの分析で落とし, 欠損は埋めるか行を落とす. `models/model.yaml` に定義を置いて学習すると, 実験の中の `inference/` に行の数と種で表を作る推論の一式を作る
- 並べるは, 入れた反応の表を骨組みの `data/` に写してそのまま読む. 学習は反応を時刻の順に分け (古い反応で学び, 新しい反応で確かめる), 2 塔のモデルで利用者ごとに上位 K 件を並べて Recall@K と NDCG を数え, 人気順 (学習用の反応の多い順) と比べる. `models/model.yaml` に定義を置くと使う (同梱の例 `two_tower_retrieval` を, `train.log` の初めの行に出る利用者と品物の数に合わせる). 学習の後に推論に使う一式を実験の `inference/` に作る (推論の段階の実験の一覧から登録して推論する. 作れない定義のときは, 理由を `train.log` に書く)
- まとめるは, 入れた表を骨組みの `data/` に写してそのまま読む (群を作る列と行を見分ける列だけを読む). 学習は行を無作為に分け, 行の埋め込みを対照学習で学び, 埋め込みを群に分けて群のまとまり (シルエット係数) で最も良いモデルを選ぶ (監視は `valid/silhouette` を大きく見る). 学習の後に, 群の安定性と群の要約を評価の表 (`evaluations/group_stability.json`, `evaluations/group_summary.json`) に書き, 列の特徴をそのまま群に分けたものと比べる. 正解が無いので今のやり方との比べと今のやり方での値の問いは出ない. `models/model.yaml` に定義を置くと使う (同梱の例 `contrastive_encoder` を, `train.log` の初めの行に出る符号化した行の幅に合わせる). 推論の一式は作らず, 学習した重み, 行ごとの群の割り当て, 列の符号化と群の中心が実験に残る
- 異常の検知は, 入れた表を骨組みの `data/` に写す. データの分析で ML-EDA の異常の検知の表を書き出し (学習用は正常の行だけで, 異常の行は検証用とテスト用に入る. 欠けた値と種類の列は前処理で無くす), 自己符号化器なら `models/model.yaml` に定義を置いて学ぶ (同梱の例 `tabular_autoencoder` を, `train.log` の初めの行に出る列の数に合わせる. 無いうちは仮のモデル). 距離はモデルの定義が要らず, 学習用の正常の行の中心と散らばりを数えるだけ. 学習の後に, 正解が少しなら上位 K 件の適合率と PR-AUC を, 無ければ度合いの分布と上位 K 行の要約を評価の表に書き, 行ごとの度合い (`anomaly_scores.csv`) と異常の度合いの一式 (実験の `inference/`. 自己符号化器の仮のモデルでは作らない) を残す. 推論の 1 回で, 度合いの高い順に人が確かめる件数の上限まで人の確かめに回す. 実験の名前の既定は受け持ちと度合いの決め方から (`anomaly_autoencoder` など)
- 効果の見積もりは, 入れた表を骨組みの `data/` に写す. データの分析で ML-EDA の介入の記録の表を書き出し (分割は処置で層を作る. ML-EDA の `describe_uplift` で群の釣り合いと配った後に決まる列を確かめる. 欠けた値は前処理で無くし, 種類の列は `one_hot` で数の列にする), `models/model.yaml` に定義を置いて学ぶ (同梱の例 `tabular_uplift` を, `train.log` の初めの行に出る列の数に合わせる. 無いうちは仮のモデル). 処置の群と対照の群で結果の 2 つの予測を学び, その差を行ごとの効果にする (S-learner では同梱の例 `tabular_uplift_s` を列の数 + 1 に合わせ, 処置の列を入力の終わりに足した 1 つの予測で, 処置を 1 にした予測から 0 にした予測を引いて効果にする). 学習の後に, 検証用とテスト用の分割ごとに Qini の係数と上位 K 割の効果の差を評価の表 (`evaluations/uplift_<分割>.json`) に, Qini の曲線を `evaluations/qini_curve_<分割>.json` に書き, 行ごとの効果 (`uplift_effects.csv`) と推論の段階が読む効果の決め方 (`uplift_estimator.json`) を実験に残し, 効果の推論の一式を実験の `inference/` に作る (仮のモデルでは作らない. S-learner では処置の列を入力の終わりに足した 1 つの予測の一式). 推論の 1 回で, 効果の高い順に配る数の上限まで配る. 配った効果は, 配る相手を無作為に分けて試して確かめる. 実験の名前の既定は結果の列と受け持ちから (`purchased_uplift` など)
- 値段を変える判断は, 入れた表を骨組みの `data/` に写す. データの分析で ML-EDA の値段を変えた記録の表を書き出し (分割は値段の段で層を作る. ML-EDA の `describe_price` で商品ごとの試した値段と, 値段と他の列の偏りを確かめる. 欠けた値は前処理で無くし, 種類の列は `one_hot` で数の列にする), `models/model.yaml` に定義を置いて学ぶ (同梱の例 `tabular_price` を, `train.log` の初めの行に出る列の数に合わせる. 無いうちは仮のモデル). 値段を入力の最後の列に入れて売れた数を学び, 学習の後に, 今の値段に候補の割合をかけた値段で売れた数を予測して, 上限を超えない候補の中で見込みの利益が最も大きい値段を商品ごとに選ぶ. 検証用とテスト用の分割ごとに, 売れた数の誤差, 弾力性と見込みの利益の比べを評価の表 (`evaluations/price_<分割>.json`) に書き, 商品ごとの選んだ値段 (`price_choices.csv`) と推論の段階が読む値段の決め方 (`price_estimator.json`) を実験に残し, ML-Inference の値段の一式を実験の `inference/` に作る (仮のモデルでは作らない). 実験の名前の既定は売れた数の列と受け持ちから (`units_price` など)
- 時間をまたぐ量の判断は, 入れた表を骨組みの `data/` に写す. データの分析で ML-EDA の需要の記録の表を書き出し (1 行が商品と発注を決める日で, 正解は先の期間の売れた数の合計. 分割は発注を決める日の順. 過去の売れた数はずらした列に, 曜日は列にする. ML-EDA の `describe_demand` で商品ごとの記録の日数, 抜けの日と在庫が 0 の日を確かめる. 欠けた値は前処理で無くし, 種類の列は `one_hot` で数の列にする), `models/model.yaml` に定義を置いて学ぶ (同梱の例 `tabular_demand` を, `train.log` の初めの行に出る列の数と学ぶ水準の数に合わせる. 無いうちは仮のモデル). 学ぶ水準の分位点の損失で学び, 学習の後に, 発注を決める日の行ごとに τ の分位点から在庫の数を引いた数の切り捨てと切り上げのうち見込みの損の小さい方を, 上限で切って発注の数にする. 検証用とテスト用の分割ごとに, 0.5 の分位点の誤差, 分位点の損失と発注の数の損の比べを評価の表 (`evaluations/demand_<分割>.json`) に書き, 発注の数 (`demand_orders.csv`) と推論の段階が読む需要の決め方 (`demand_estimator.json`) を実験に残し, ML-Inference の需要の一式を実験の `inference/` に作る (仮のモデルでは作らない). 実験の名前の既定は日ごとの売れた数の列と受け持ちから (`units_demand` など)
- 書き出すと対話のボタンは「書き出しました」になり, 書き出すディレクトリ, 実験の名前, 上書きのどれかを変えるまで押せない (同じ場所に書き出し直すと, 上書きを選ばない限り既にあるファイルの誤りになるため)
- 書き出した場所 (学習のプロジェクト, データセットの書き出し先, モデルの定義の置き場) は問題に記録され, 右の「後ろの段階に渡す値」の「学習のプロジェクト」に出る. 後ろの段階はこの記録から場所を読むので, 手で写さなくてよい. 別の場所に書き出し直すと記録も置き換わる
- 書き出した config には学習に要るもの (`requires`) が書かれ, 学習・評価の段階の「学習の準備」で確かめて入れられる. 4 章でデータを入れ, 7 の「今のやり方をデータで書くと」に答えていれば, 学習のスクリプトは検証用とテスト用で今のやり方と比べた評価を残す
- 書き出した README の「次にすること」の順に, データセット (データの分析の段階) とモデルの定義 (モデルの作成・選定の段階) を置いて学習・評価の段階で学習し, 実験の中の推論の一式を推論の段階で登録する. 推論の段階で一式に問題をつなぐと, 7 の損得が推論の意思決定の既定になる

「problem.yaml」のボタンで, 問題のファイルを保存する.

## 7. 他のアプリとの共有

開いている問題のファイルを他の段階 (データの分析の段階の書き戻しなど) が書き換えると, 画面に戻ったときか 10 秒以内に読み直す. 外で変わった問いの書きかけは, 外の値に置き換わる.

画面は API を使って動くが, API は画面のためのもので, スクリプトから問題を設定する場合は ML-Quest を直接使う.

## 8. 置き場

既定は `~/.ml-pathfinder/` (環境変数 `ML_PATHFINDER_HOME` で変えられる). 問題は `problems/<識別子>/problem.yaml` に, 入れたデータの写しは `problems/<識別子>/data/` に置く.

## 9. 困ったとき

| 症状 | 対処 |
| --- | --- |
| 画面を開いても読み込めない | 端末に出た最新の URL (`/api/auth?token=…`) を開き直す. 起動し直すとトークンが変わる |
| ポート 8770 が使われている | `make serve PORT=8800` のように別のポートで起動する |
| 一覧に「(読めない問題 …)」と出る | 置き場の `problem.yaml` が壊れている (YAML として読めない, 版が無いなど). 開くと理由が出る. 要らなければ消す |
| 開くと「新しい版 (format_version: …) の問題のファイルです」と出る | 新しい版の ML-Quest で書いた問題. ML-Pathfinder を新しくしてから開く. ファイルは壊れていないので消さない |
| 「学習のプロジェクトを書き出す」を押せない | 骨組みを組めない (機械学習を使うかに答えていない, 受け持ち, 目的の列, タスク, 指標などに「直す」がある, 書き出せない受け持ち). 理由はボタンの下に出る |
| 書き出す対話で「書き出す」を押せない | 「直す」が残っている. 一覧の問いを直すか, 「それでも書き出す」を選ぶ (書き出した README に一覧が残る) |
| 書き出すと「直すところが … 件残っています」と出る | 対話を開いた後に直すところが増えた (データの確かめなど). 出た一覧を確かめ, 直すか「それでも書き出す」を選んで押し直す |
| 確かめに「データの場所は, ファイルかディレクトリの場所を文字で書いてください」などの形の誤りだけが出て, 他の確かめが消えた | 手で書いた `problem.yaml` のデータの場所 (`data`) が数や並びになっている. 形の誤りがあるあいだ, ML-Quest は他の確かめをしない. 確かめの「問いへ」で 5 の「手元のデータは」に移り, 「データを外す」か「データを入れ直す」(またはファイルのデータの場所を文字の場所に直す) と, 他の確かめが戻る |
| 「問題のファイルが他 (…) で変わったので, 読み直しました」と出て答えが置き換わった | 他の段階 (データの分析の段階の書き戻しなど) が同じ問題を書き換えた. 外の値を見てから答え直す |
| アプリを止めたい | `make serve` を動かしている端末で Ctrl+C |
